  close control), camera preview area, 开始扫描 primary, 从相册选择 secondary,

## Setup

- Backend on 8080 (`java -jar target\gogo-backend-0.0.1-SNAPSHOT.jar`), frontend
  Vite dev server on 5173 (`npm run dev`). Dev database migrated V1–V5.
- Issue an open invitation for the fixture trip via REQ-004 flow (`POST
  /api/trips/<id>/invitation`, `X-User-Id: 1`) and read the fresh `<token>`
  from the response `joinPath` (`/join/<token>`); `<token>` is 32-char
  lowercase hex. Compose `<abs>` = `http://localhost:5173/#<joinPath>` and
  `<hash>` = `#<joinPath>` for use in rows below.
- Camera scenarios (I-1..I-3, I-5..I-7) require either a real camera showing
  a pre-burned QR of the fixture URL, OR a virtual-camera app streaming a
  still image of that QR, OR a Waiver at local-verify time with the fallback
  proof running through the manual-link path (I-8) instead. If camera cannot
  be exercised, record the row as **Partial** with reason, never fake Pass.
- Cross-browser smoke note (advisory, non-gate): run I-1..I-2 on one Chromium
  desktop and one WebKit mobile emulation; note device/browser in Observed.
- Screenshot naming: `s<group>-<index>-<slug>.png` in `frontend/logs/`
  (gitignored). Reference filenames from Observed column.
