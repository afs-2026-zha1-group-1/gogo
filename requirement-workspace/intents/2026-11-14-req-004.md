## Verbatim story intent

**US-008.** As a trip organizer, I would like to obtain and share an invitation
link and allow QR code format too, so that my friends can join the correct trip.
Required layers: Frontend yes, Backend yes, Database yes (read/write).
AC: (1) Alice organizes "Singapore Friends Day" with an unconfirmed main plan;
she obtains and copies an invitation link; the copied link opens an invitation
for that trip and can be used by an invited traveler to join. (2) Ben is a member
but not the organizer; he requests a new invitation link directly; the request is
denied and no invitation is created. (3) Eve scans the QR code; the decoded link
opens the same invitation and the same joining rules apply as for the displayed
link, including explicit acceptance, duplicate-membership protection, and joining
closure after main-plan confirmation.
Design scope: organizer invitation link, copy action, and a scannable QR encoding
the same invitation URL. The prototype QR is decorative; production must encode
the real URL. Native/social sharing fallback, expiry configuration, and revocation
controls are optional, not MVP requirements. UI reference: Screen 4.

**US-010.** As an invited traveler, I would like to see the trip name and accept a
valid invitation before main-plan confirmation and join once under my identity,
so that I can join the correct trip without duplicate memberships.
Required layers: Frontend yes, Backend yes, Database yes (read/write).
AC: (1) Signed-in Eve is not a member and holds a valid invitation link to
"Singapore Friends Day" with an unconfirmed main plan; she opens the link; she
sees Singapore Friends Day before accepting without receiving private itinerary
or preference data. (2) Eve submits acceptance twice under the same identity; she
has exactly one membership in the trip. (3) The main plan is confirmed and Eve is
not a member; she accepts an otherwise valid invitation; joining is rejected and
the existing member list remains unchanged.
Design scope: invitation preview, explicit acceptance, and joined state. Use the
signed-in identity from the acceptance criteria, not the pictured
nickname-as-identity demo; do not expose additional private information before
acceptance. UI reference: Screen 5.

**US-012.** As an invited traveler, I would like to be told when an invitation is
invalid or revoked without seeing private trip data, so that I know the link
cannot be used to join.
Required layers: Frontend yes, Backend yes, Database yes (read).
AC: (1) Eve holds an invalid invitation link that does not refer to any trip; she
opens it; she sees an unusable-invitation message and receives no private trip
data or membership.
Design scope: generic unusable-invitation message without private trip data. The
pictured reminder action and expiry wording do not require a notification
workflow or expiry configuration. UI reference: Screen 6.

All three bodies state that acceptance criteria and `acceptance-test-fixtures.md`
govern behavior and sample values, that screenshots are presentation references
only, and that required error, empty, loading and permission states must be
implemented even when not pictured.
