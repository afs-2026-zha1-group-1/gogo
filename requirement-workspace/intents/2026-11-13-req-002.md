## Interpretation notes

- Source 1 resolves all three inherited open questions at once. It **reverses**
  two earlier decisions: the H2 substitution (REQ-001 OQ-1) and the `text/plain`
  body (REQ-001 design D4).
- Source 2 fixes the wire contract. `{"message":"Hello World"}` is a single-field
  JSON object, not a bare string and not a nested envelope.
- The JSON ruling contradicts the merged Living Spec
  (`openspec/specs/greeting/spec.md`, scenario "Stored greeting is returned":
  "the response body is exactly `Hello World`"). A merged spec cannot be edited
  in place, so this change carries a **MODIFIED** delta for that requirement.
- The SQLite ruling does **not** contradict the Living Spec: the storage
  requirement is engine-agnostic ("an embedded database that needs no separate
  database service"). SQLite is recorded in `design.md`, not in the spec, per the
  AC-4 rule against implementation detail in acceptance criteria.
- Source 3 is a toolchain unblock, not product scope. `sqlite-jdbc` was absent
  from the local Maven cache and Maven Central is unreachable from this machine
  (TLS `certificate_unknown`). The supplied corporate settings file was installed
  at `~/.m2/settings.xml` with one deviation: its `localRepository` pointed at a
  non-existent `D:\software\apache-maven-3.0.4\repository`, which would have
  forced a full re-download, so it was overridden to the existing warm cache
  `C:\Users\SUNJO\.m2\repository`. The file holds credentials and is never
  committed or printed.
