## Verbatim story intent

**US-064.** As a traveler, I would like every trip screen to live inside one
mobile-scaled app shell with a persistent bottom dock, so that I can move between
the main areas without losing context and the whole product keeps the same
phone-style frame. Required layers: Frontend yes, Backend no (reuse existing
reads), Database no.

Acceptance criteria:
1. Any in-app route renders inside the shell: a centered column at most 430 px
   wide, 100 dvh tall, bottom dock fixed below the scrolling content with
   safe-area padding, using the tokens and component language of
   `ui-design-reference`.
2. The dock has four tabs in order 仪表盘 / 行程 / 分队 / 成员, each with an icon
   and a text label; the active tab is highlighted; switching updates the hash
   route without a full page reload and keeps the selected identity.
3. The 仪表盘 tab shows the existing home content (greeting status, create entry,
   identity scaffold) and remains the default route.
4. The 行程 tab shows the existing trip details screen (hero, information rows,
   organizer invitation panel); when no trip is selected, a text empty state
   offers "创建行程" and "按编号打开行程" instead of inventing data.
5. The 分队 or 成员 tab shows an honest text placeholder that the feature is not
   implemented yet and links back to 行程; no demo members, routes or statuses
   are fabricated.
6. An invitation link `#/join/<token>` or an unusable link stays full-screen
   without the dock, so an invited guest is not shown in-app navigation before
   joining.
7. The identity switcher stays available in the shell and continues to set
   `X-User-Id` on every request; it remains labeled as a scaffold, not a login.
8. A text-only verification pass: each tab activated shows a unique visible
   heading or state; switching works in both directions; browser back/forward
   follows the tab history without losing the selected identity.
9. Existing acceptance behavior is unchanged: create validation, trip-details
   permission, invitation panel and join flow behave exactly as today.

Page function confirmation (text only): 仪表盘 `#/` ← `Home.jsx` (default tab);
行程 `#/trips/<id>` ← `TripDetails.jsx` (+ no-trip empty state); 行程 `#/create`
← `CreateTrip.jsx` (back returns to 行程); 分队 `#/split` and 成员 `#/members` are
new text placeholders; `#/join/<token>` ← `Join.jsx` stays full-screen, no dock.

Out of scope (verbatim): real split planning / route generation / route switching
(US-038–US-062); member list and readiness (US-013); dashboard status aggregation
(US-061) and a list-all-trips endpoint; backend or database changes;
authentication; new demo data.

The body states screenshots are presentation references only; the pictured fixed
demo members, routes and statuses are not requirements.
