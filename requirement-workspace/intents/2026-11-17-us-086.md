## 原始验收条件（issue #113 初版）

1. 标题为「队伍路线」，右上角是「发起分队」按钮，替代底部旧按钮。
2. 页面主体用 git 风格路线图展示全队的分头、并行与会合。
3. 每个节点可点击，弹层展示当前节点需要做的事。
4. 状态覆盖：无草稿、已取消、无已确认主线、无权限/读取失败。

## 会话裁决（2026-11-17，P1 澄清）

## 现状事实（P1 已核）

- 旧页面：`frontend/src/features/split/screen-start.tsx`，标题「智能分队」，底部「发起分队草稿」，含 fork-join 示意图与规则卡；已被原型新设计取代但尚未在应用内实现。
- 读接口：
  - `GET /api/trips/{tripId}/split-draft` → `SplitDraftDetail`：`status`、`groups`、`mainPlanStops[{id,name,startAt,endAt}]`、`departureStopId/reunionStopId`、`departureAt/reunionAt/windowMinutes`、`routes[GroupRoute]`。
  - `GroupRoute`：`groupLabel`、`activityName`、`activityMinutes`、`travelLegsMinutes[]`、`bufferMinutes`；**无逐节点时刻/地点/费用/任务**。
  - `GET /api/trips/{tripId}/main-plan` → `PlanResponse`：`confirmed`、`costPerPersonCents`、`stops[{name,startTime,endTime,travelMinutesToNext,interests}]`；没有草稿时用于渲染主线。
- 数据来源差异：有草稿时主线节点取 `split-draft.mainPlanStops`（`plan_node` main 行，ISO 时刻）；无草稿时取 `main-plan.stops`（本地 `HH:MM`）。两者字段与时区表示不同，展示层需分别格式化。
- 状态机：`active` 可编辑；`confirmed` 只读；`cancelled` 可被重建（US-050）。已确认时旧页面不出现发起入口，改为「查看已确认分队」。
- 权限：split-draft 成员可见；401/403/404 语义由后端给出；主线读取同样成员范围。
- 前端能力：`useSplitDraft` 使用 TanStack Query 并 5s 轮询；`SplitLayout` 已支持 appbar 右侧插槽；UI token 与图标已具备；无图表库依赖。

## 依赖与所有权

- US-037 已确认主线（读）；US-038 唯一草稿（读/状态）；US-042 分组与路线（读）；US-043 时间窗（读）；US-049/050 确认/取消（只读消费其状态）。
- 个人路线与倒计时归 US-052 / US-063；成员名册归 US-013；本故事不重复实现。
