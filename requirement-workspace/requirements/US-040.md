## Intent

把分队草稿的「分组」从服务端按顺序自动切分，变成成员可自选、全员可见、确认前被校验的一等状态：每位成员只能移动自己，路线按当前分组标签重新生成，组织者在确认时能确认「每组都有人、每人只在一组」。

## Actors and boundaries

- 读分组：任意行程成员（`GET /api/trips/{tripId}/split-draft` 已 member-only 返回 `groups`）。
- 改分组：任意行程成员，但**只移动自己**；请求体不含 `memberId`，服务端以会话账号 `AccountPrincipal.id`（即 `groups` 元素 `app_user.id`）为目标。
- 重新生成路线：仅发起人（沿用 `NOT_SPLIT_INITIATOR`）。
- 确认：仅组织者（沿用 `requireOrganizer`）。
- 前端拥有分组卡渲染、成员名映射（复用 `GET /api/trips/{id}/members`）、切组反馈与提示；合法性判定（能否切、分组是否完整）归后端。

## In scope

- 新增 `PUT /api/trips/{tripId}/split-draft/assignment`：认证会话；body `{groupLabel, draftVersion}`；服务端校验成员资格 → 活跃草稿 → 版本 → 目标组别，把**调用者本人**在 `groups` 中从原组移出并加入目标组；成功后 `draftVersion + 1`；**不改动已生成的 `routes` 与已保存边界**。
- `groups` 结构恒为 `{"A": [...], "B": [...]}` 两个键（允许空数组），元素为 `app_user.id`（即 `trip_member.user_id`，与 `initiatorMemberId`、会话主体同源）。
- 草稿初始分组语义变更：发起草稿时 `A = 全部行程成员`、`B = []`（取代 `partitionGroups` 的前一半 A / 余下 B）。
- 生成路线前置校验：`POST /api/trips/{tripId}/split-draft/routes:generate` 在既有前置（成员/发起人/活跃/边界/版本）之后，增加分组完整性校验；不完整 → `409 SPLIT_DRAFT_INCOMPLETE`，`error.details.missing` 含分组项；完整 → 按**当前** `groups` 的 A/B 标签成对生成。
- 确认前置校验：`POST /api/trips/{tripId}/split-draft:confirm` 的 `missingDraftParts` 增加分组项（空组 / 成员漏分组 / 成员重复分组），与既有 `boundaries`、`routes.A/B` 同列返回。
- 分组完整性判定口径：A、B 两组均非空；`groups` 的成员集合 = 该行程当前 `trip_member.user_id` 集合（无漏、无多、无重复）。
- Screen 13「分组与路线」新增分组卡：A 组 / B 组（组名、人数、成员名）、「我」标记、切组控件；切换成功后刷新草稿并提示「分组已更新，路线仍为上次生成的版本，可点击重新生成」。
- Screen 13 卡片说明文案移除「分组移动本期不开放」；「重新生成」按钮文案与行为沿用（按当前分组标签生成）。
- Screen 15 复核屏把 A/B 组展示从 memberId 原串改为成员名（复用同一份成员名册）。

## Out of scope

- 替他人改组、组织者调整分组、批量分配（AC 明确禁止）。
- 新增表、`split_draft` 表结构变更、Flyway 迁移（`document` JSON 已含 `groups`）。
- 已确认分队的分组再调整（只能取消后重建，沿用 US-050 规则）。
- 路线与成员的绑定关系（路线按组标签存活动与时长，不关联具体成员，本故事不改）。
- 分组偏好推荐、按兴趣自动分组算法（现 provider 为固定夹具候选）。
- 分队发起、边界选择、会合时间校验、确认/取消的既有语义（US-038/039/043/049/050，本故事只回归）。
- 成员名册端点与页面（US-013 已交付，只复用）。
- 通知、邮件、实时推送。

反向 / 边界：

- R1 无认证会话调用 `PUT .../assignment` → `401 MEMBER_REQUIRED`。
- R2 非该行程成员调用 → `403 NOT_A_MEMBER`，响应不含任何分组数据。
- R3 不存在的 tripId → `404 TRIP_NOT_FOUND`。
- R4 无活跃草稿（无行 / confirmed / cancelled）→ `409 SPLIT_DRAFT_NOT_ACTIVE`。
- R5 携带过期 `draftVersion` → `409 STALE_DRAFT_VERSION`，`groups` 与版本均不变。
- R6 `groupLabel` 不是 `A`/`B` → `400`，错误码见 OQ-9；无持久化。
- R7 请求体夹带他人 `memberId` / `groups` 字段 → 被忽略或 `400`，任何情况下不移动他人。
- R8 改组不触碰 `departureStopId`、`reunionStopId`、`routes`、`initiatorMemberId`、`mainPlanVersion`、`status`。
- R9 改组不新增/删除 `trip_member` 行，不改变任何成员的角色或归属。
- R10 「分组已改但未重新生成」不构成确认拒绝理由（BQ-2：确认只看边界、路线存在、分组完整性）。

## Constraints

- 身份：会话主体（`AccountPrincipal.id` = `app_user.id`）；`groups` 元素为 `app_user.id`，与 `initiatorMemberId` 与会话主体同源，**无需二次映射**到成员行（`trip_member` 为复合主键、本身无独立 id）。
- 版本：`draftVersion` 乐观锁；任何分组变更 +1；`confirmed`/`cancelled` 不改版本。
- 数据：只读写 `split_draft.document` JSON 的 `groups` 字段；**零迁移**。
- 错误词汇：不新增错误码（`MEMBER_REQUIRED` / `NOT_A_MEMBER` / `TRIP_NOT_FOUND` / `SPLIT_DRAFT_NOT_ACTIVE` / `STALE_DRAFT_VERSION` / `SPLIT_DRAFT_INCOMPLETE` / `NOT_SPLIT_INITIATOR` 全部已存在）；`groupLabel` 非法见 OQ-9。
- 明细形状：沿用 `error.details.missing`（字符串数组），分组项命名为 `groups.A`、`groups.B`、`groups.unassigned`、`groups.duplicate`。
- 前端：沿用 shadcn/ui + `@theme` tokens；Split 流程使用 TanStack Query hooks（`features/split/hooks.ts`）；不新增路由、不改 4 段 stepbar。
- 成员名：前端复用 `GET /api/trips/{id}/members` 的 `displayName`；detail 响应不新增名字段。
- 回归：发起草稿、边界保存、会合校验、确认/取消的既有场景不变。

## Context

- 现状：`groups` 在 `SplitDraftDocument.initial()` 时由 `partitionGroups()` 写入；`withBoundaries` / `withRoutes` / `confirmed` / `cancelled` 均原样保留 `groups`。
- `generateRoutes` 只按 `draft.groups().keySet()` 逐组取候选，成员身份不参与；`BranchCandidateProvider` 为固定夹具实现。
- `missingDraftParts()` 只产出 `boundaries`、`routes.A`、`routes.B` 三个字符串。
- Screen 13 现状：分组卡显示「自动分组 / A 组 N 人 / B 组 N 人」，说明文字为「分组由夹具按偏好齐全分区；本期不开放成员移动控件」，副标题为「成对生成 · 分组移动本期不开放」。
- Screen 15 现状：`Row label="A 组" value={groups.A.join(" / ")}`，展示的是 memberId。
- 成员名册：`GET /api/trips/{id}/members`（US-013）返回成员行（含 `displayName`）；`Members.tsx` 已在消费。
- 原型差异：issue #84 附件允许调整其他成员；本故事按 AC 收紧为「只能改自己」，原型仅作布局参考。
- 历史预留：`SplitRouteGenerationApiTest` 中存在负向用例 `generateRoutes_groupMoveEndpoint_notImplemented`，断言 `POST .../split-draft/groups:move` 返回 404/405。本变更按 BQ-1 采用 `PUT .../assignment` 命名，不采用 `groups:move`；P4 必须删除或改写该负向断言（已登记在 impact §4）。

## Affected capabilities

- `splits`：**ADDED**「Member group assignment」（`PUT .../split-draft/assignment`，仅本人、active、版本条件、保留 routes）。
- `splits`：**MODIFIED**「Split draft start」（初始分组 `A = 全部成员 / B = 空`，取代前后均分）。
- `splits`：**MODIFIED**「Group route generation」（分组完整性前置取代「夹具保证」，不完整 `SPLIT_DRAFT_INCOMPLETE`；按当前分组标签生成）。
- `splits`：**MODIFIED**「Split confirmation」（`missingDraftParts` 增加分组项与明细命名）。
- 前端 Screen 13 / Screen 15：分组卡与成员名展示（属 `splits` 显示契约，不新增 `app-shell` requirement）。
- `trips`、`invitations`、`main-itinerary`、`preferences`、`auth`、`app-shell`：不改，仅作为数据来源（成员名册、行程成员）被消费。
