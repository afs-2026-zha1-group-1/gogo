## Intent

Give the product one recognizable phone frame: a centered mobile column with a
persistent bottom dock so a traveler moves between 仪表盘 / 行程 / 分队 / 成员
without losing context or identity. The shell is placement and navigation
only — every existing screen keeps its contract, and areas that do not exist
yet say so honestly instead of showing demo data. An invited guest opening a
join link never sees in-app navigation before joining.

## Actors and boundaries

The `X-User-Id` header remains a **scaffold-level stand-in for authentication**
(REQ-003 §Actors): trusted without verification, never a security control.
The switcher stays labeled as a scaffold, not a login.

Boundary ownership: the new `app-shell` capability owns the frame, the dock,
the tab-to-route mapping, the no-trip empty state and the two placeholder
pages. `greeting`, `trips` and `invitations` keep ownership of their data and
endpoints; the shell composes their existing pages and never re-decides
permission, membership or closure. Join/unusable screens are excluded from
the dock by the shell, not by changes to the join flow itself.

## In scope

- Shell frame around every in-app route: centered column at most 430 px wide,
  100 dvh tall, scrolling content above a fixed bottom dock, safe-area
  padding, using the existing `ui-design-reference` tokens and component
  language (already mirrored by `frontend/src/app.css`).
- Bottom dock: four tabs in order 仪表盘 / 行程 / 分队 / 成员, each icon + text
  label, visible active highlight, hash-route switching without full reload,
  selected identity preserved; browser back/forward follows tab history.
- 仪表盘 tab: existing `Home` content (greeting status, create entry) under the
  shell; `#/` remains the default route.
- 行程 tab: existing `TripDetails` (hero, information rows, organizer invitation
  panel) under the shell; a no-trip empty state with text and exactly two
  actions — 创建行程 and 按编号打开行程; `CreateTrip` reachable from the shell
  with its back action returning to 行程.
- 分队 (`#/split`) and 成员 (`#/members`): honest text placeholders stating the
  feature is not implemented yet, each linking back to 行程.
- Join exclusion: `#/join/<token>` (preview, accept, joined, closed) and the
  unusable state render full-screen without the dock; today's identity
  scaffold bar and join behavior are retained there.
- Text-only verification surface: every tab page carries a unique visible
  heading or state so the forward/reverse switching check needs no
  screenshots or demo data.

## Out of scope

- Real split planning, route generation or route switching (US-038–US-062).
- Member list and readiness (US-013).
- Dashboard status aggregation (US-061) and any list-all-trips endpoint.
- Backend or database changes of any kind; authentication; new demo data
  (no fabricated members, routes or statuses on any surface).
- Changes to create validation, trip-details permission, invitation panel or
  join flow contracts (REQ-001/003/004 behavior is reused verbatim).
- New frontend dependencies, i18n, CI job structure changes.

## Constraints

- React 19 + Vite frontend, plain CSS with the existing token set — unchanged
  stack; no new dependency required by any AC.
- Hash router stays the shared mechanism (REQ-004 design D7); no full page
  reload on tab switch; identity stays App-level state.
- `X-User-Id` scaffold unchanged; never presented as a security control.
- Repository documentation in English (`AGENTS.md`); two-job CI reused
  unchanged (frontend build job covers this change).
- UI follows `ui-design-reference/` style (screen 01 dock; 02/03 content;
  16/17 dock on in-progress screens). Screenshots are presentation references,
  not acceptance criteria.
- Depends on REQ-001/003/004 frontend code being present (it is, on the
  current branch); REQ-003 PR #30 and REQ-004 PR #31 are both merged
  (2026-11-15), so the stacking order is satisfied.
