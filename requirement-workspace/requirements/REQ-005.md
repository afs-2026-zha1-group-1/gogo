## Discovery decision

**Go - 2026-11-16.** The actual checkout supports one bounded frontend
TypeScript migration with no backend, database, or API-contract change. The
baseline corrections and the user's scope decision are recorded in the intent
capture.

## Intent

Convert every current frontend JavaScript source file and the Vite config to
TypeScript, so frontend code is consistently type-checked without changing what
visitors see or how existing requests behave.

## Actors and boundaries

- Frontend developers gain compiler feedback for components, props, state, API
  payloads, and the application entry point.
- Visitors continue to use the current home, trip, and invitation screens.
- The frontend continues to consume the existing backend API. The backend,
  database, and API ownership boundaries do not change.

## In scope

- Convert the nine current source files and Vite config:

  | Current file | Target |
  |---|---|
  | `frontend/src/App.jsx` | `frontend/src/App.tsx` |
  | `frontend/src/main.jsx` | `frontend/src/main.tsx` |
  | `frontend/src/api.js` | `frontend/src/api.ts` |
  | `frontend/src/Icons.jsx` | `frontend/src/Icons.tsx` |
  | `frontend/src/pages/Home.jsx` | `frontend/src/pages/Home.tsx` |
  | `frontend/src/pages/CreateTrip.jsx` | `frontend/src/pages/CreateTrip.tsx` |
  | `frontend/src/pages/TripDetails.jsx` | `frontend/src/pages/TripDetails.tsx` |
  | `frontend/src/pages/Join.jsx` | `frontend/src/pages/Join.tsx` |
  | `frontend/src/pages/InvitationPanel.jsx` | `frontend/src/pages/InvitationPanel.tsx` |
  | `frontend/vite.config.js` | `frontend/vite.config.ts` |

- Update `frontend/index.html` and every affected import to use the TypeScript
  entry and renamed modules.
- Add the TypeScript compiler configuration and only the development-time
  compiler/type packages needed to check the existing application.
- Ensure the build runs the TypeScript project check before Vite bundling.
- Provide proper types for API responses, component props, state, and DOM events;
  guard the `#root` lookup before calling `createRoot`.
- Preserve the current Vite React plugin, port 5173, and `/api` proxy target
  `http://localhost:8080`.
- Verify the TypeScript check, production build, development startup, and
  existing browser flows.

## Out of scope

- Backend, database, API contract, or persistence changes.
- New features, route changes, visual redesign, or refactoring unrelated to
  TypeScript compilation.
- Adding a new test framework or lint tool.
- Adding an `@` import alias or Tailwind plugin. Neither exists in this
  checkout, and the user confirmed those attachment statements are stale.
- Implementing a B-chain split flow or introducing `router.tsx`; neither exists
  in the current frontend.
- Changes to the existing greeting, trip, or invitation business behavior.

## Scenarios and AC hints

| id | Scenario | Observable outcome |
|---|---|---|
| AC1 | Inspect frontend source after migration | No `.js` or `.jsx` source remains under `frontend/src` or in the frontend root; `node_modules` and `dist` are excluded. All ten inventoried files have the `.ts`/`.tsx` targets listed above. |
| AC2 | Load the frontend entry and modules | `frontend/index.html` loads `/src/main.tsx`; imports resolve to the renamed modules. |
| AC3 | Type-check the frontend | The TypeScript project build reports zero errors. The migrated code has no `any` escape-hatch or `@ts-ignore`, and the root element is checked before mounting React. |
| AC4 | Build and start the frontend | `npm run build` succeeds with type-checking enabled; `npm run dev` starts on port 5173 and `/api` continues to proxy to `http://localhost:8080`. |
| AC5 | Open the home page with the API available or unavailable | A successful `GET /api/greeting` response with JSON body `{"message":"Hello World"}` still displays `Hello World`; an unreachable or unsuccessful request still displays the existing load-failure state instead of the greeting. |
| AC6 | Use current application routes and identity scaffold | `#/`, `#/create`, `#/trips/<id>`, and `#/join/<token>` retain their existing behavior; changing the scaffold identity continues to send the corresponding `X-User-Id` on identity-bound requests. |
| AC7 | Exercise trip and invitation flows | Trip creation/details, invitation preview/acceptance, organizer-only invitation controls, QR/link actions, and existing loading/error/denied states behave as before. No user-visible behavior changes are introduced by the migration. |

## Constraints

- The current frontend uses React 19 and Vite 8 with the React plugin.
- The frontend currently has no TypeScript configuration; `npm run build`
  currently runs only `vite build`.
- The current app uses a hash router in `src/App.jsx`; there is no
  `router.tsx`.
- The Vite config currently exposes port 5173 and proxies `/api` to
  `http://localhost:8080`. There is no `@` alias or Tailwind plugin.
- The frontend has no test framework. This requirement does not add one.
- Repository documentation is written in English.

## Affected capabilities

The application-architecture touchpoint is the frontend build and browser
application. No existing product capability is intended to change: the
`greeting`, trip, and invitation behavior remains as-is. The change is a
developer-facing language/build constraint, not a new browser capability.

## Open questions

None at application-architecture granularity. Exact compiler options and
development-only type packages are implementation-design choices; they do not
change app boundaries, runtime topology, or acceptance outcomes.
