## Intent

补齐 B 拆分链的最后一段：`splits` 能力当前止步于「校验结论」（`POST .../routes:check-timing`，零写库），草稿可以生成但永远无法定稿，也无法主动作废。本变更提供两个收口动作 —— 组织者确认（把当前版本冻结为唯一拆分方案）与发起人取消（放弃未确认草稿并为替换让路），二者共享同一 Screen 15 与同一草稿状态机（`active` → `confirmed` / `cancelled`），因此打包为一个 change。

## Actors and boundaries

- 确认 = **组织者专属**（US-049 AC3）；取消 = **草稿发起人专属**（US-050 AC3）。二者都是成员，需先过 `MemberGuard`（身份 → 行程存在 → 成员资格）。
- 非组织者确认 → `403 NOT_SPLIT_ORGANIZER`（本期新增，与既有 `NOT_SPLIT_INITIATOR` 对称）；非发起人取消 → `403 NOT_SPLIT_INITIATOR`（复用）。
- 读写边界：确认/取消都是**写**操作（Database: Yes Read/Write），但**不新增表、不新增迁移** —— 状态落在既有 `split_draft.document` JSON 的 `status` 字段（Living Spec 早已预留 `cancelled`）。
- 前端只渲染服务端结论，不自行判定可行性；`confirmable` 之类的客户端声明**不参与**服务端判定（US-049 AC2 的反向用例正是「客户端说 true、服务端算出 125 分钟」）。

## In scope

- **US-049 确认**：`POST /api/trips/{tripId}/split-draft:confirm`（`{draftVersion}`）—— 守卫 → 组织者判定 → 活跃草稿 → 版本匹配 → 草稿完整性（边界 + 两条路线）→ **服务端从草稿文档复算两条路线的时间可行性**（复用 `ReunionTimingCalculator`，超窗或缺输入均判不可行）→ 单事务把文档 `status` 置 `confirmed`。成功后草稿锁定：后续 `PUT boundaries`、`POST routes:generate` 返回 `409 SPLIT_DRAFT_NOT_ACTIVE`。
- **US-050 取消**：`POST /api/trips/{tripId}/split-draft:cancel`（`{draftVersion}`）—— 守卫 → 活跃草稿 → 发起人判定 → 版本匹配 → 把文档 `status` 置 `cancelled` 并清除该行程的 split 路线节点（`plan_node` 的 `split-a`/`split-b`），主线节点不动。已确认草稿不可取消（`409 SPLIT_DRAFT_NOT_ACTIVE`）。
- **替换草稿**：取消后 `POST /api/trips/{tripId}/split-draft` 在**同一行**（`split_draft.trip_id UNIQUE` 不变）以调用者为新发起人重建文档（`draftVersion = 1`、`status = active`、边界/路线清空），即「未使用额度可用于替换」。
- **Living Spec 漂移修正（P0 D1）**：在 delta 内以 **MODIFIED** requirement 把 `splits` 的身份（`X-Member-Id` → `X-User-Id`，`trip_member.id` → `app_user.id`）、草稿载体（`trip.split_draft` 列 → `split_draft` 表）、迁移编号（V2 → V4）纠正到与 main 一致。
- **前端 Screen 15**：`/trips/:tripId/split/confirm`（复核路线对/分组/边界 + 校验状态 + 组织者确认按钮 + 发起人取消动作），强制 error / empty（无草稿）/ loading / permission（非组织者不可确认、非发起人不可取消）四态，含 `confirmed` 与 `cancelled` 两个终态呈现。
- 错误契约扩展：新增 `NOT_SPLIT_ORGANIZER` 403、`SPLIT_TIMING_INFEASIBLE` 409（带 `totalMinutes`/`overrunMinutes`/`missingInputs` 明细）；其余复用既有 13 码。
- 测试：`SplitConfirmApiTest`、`SplitCancelApiTest`（红先），域层补充 `SplitDraftDocument` 状态迁移单测；夹具矩阵 CF1–CF6 / CN1–CN5。

## Out of scope

- 真实地图/路径供给（R2）、路径重算与重新生成策略调整（REQ-006 既有语义不变）。
- 拆分历史与审计表：单行模型只保留最新状态，被替换的 cancelled 文档不保留（如需审计另立需求）。
- 确认后的重新规划/回滚（R2；已确认即冻结）。

- 多草稿并存、半边界、分组移动控件（沿用既有 non-goals）。
- 会话认证/真实鉴权（身份仍是 `X-User-Id` 信任模型）。

## Constraints

- 技术栈不变：Spring Boot + JdbcTemplate + 嵌入式 SQLite + Flyway（无 ORM）；React + Vite + TS（Screen 15 用 `features/split/` 现有结构 + shadcn/ui 组件）。
- **无新表、无新迁移**：确认/取消只改 `split_draft.document` 的 `status` 与 `updated_at`；`trip_id UNIQUE` 保持不变（替换在同一行重建）。
- 身份 = `X-User-Id`（`app_user.id`）；MVP 不校验签名，不得描述为安全控制。
- 响应统一 `{data, error}` 包封套；`error.code` 为契约，`error.message` 自由。
- 状态迁移只允许 `active → confirmed`、`active → cancelled`、`cancelled → active`（重建）；不允许 `confirmed → *`。
- 确认的原子性：文档状态 + （无其他写入）；取消的原子性：文档状态 + split 路线节点删除在同一事务内。
- 仓库文档按 AGENTS.md 惯例撰写；本条目与后续产物使用中文（用户偏好）。
- 屏幕 15 的 error/empty/loading/permission 四态为强制项；演示动画不算验证证据。
