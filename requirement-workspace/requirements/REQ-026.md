## Intent

把「提交」做成一次可验证的服务端状态迁移，而不是一次前端点击或动画：

1. **提交 = 状态**：`pending`（无 `submission` 行）→ `ready`（有行）。保存偏好**不**产生就绪。
2. **两种就绪**：`ready + noPreference=false`（用我的个人值）与 `ready + noPreference=true`（用默认画像，丢弃我的个人值）。
3. **沉默≠同意**：既未提交也未选无偏好的人保持 `pending`，并且在生成侧投影里**根本不出现**。

## Actors and boundaries

- **身份来源**：`X-User-Id` 请求头，整数，指向 `app_user` 主键。缺失、非整数或指向未 seed 用户 → `401 USER_REQUIRED`。
- **成员判定**：三个端点都要求调用者属于该 `tripId` 的 `trip_member`，否则 `403 NOT_A_MEMBER`；`tripId` 不存在 → `404 TRIP_NOT_FOUND`；顺序 identity → trip → membership，复用 `TripRepository.findUserId` / `isMember`。
- **写边界**：只能写 header 指定成员自己的 `kind='submission'` 记录；无「替他人提交」的合法路径；提交不修改任何其他 kind 的行。
- **读边界**：`readiness` 与 `effective` 都返回全员视角数据（与 REQ-019/020/024 的 GET 口径一致），前端只渲染需要的那部分。
- **前端边界**：不做本地持久化与乐观置就绪；就绪状态以服务端响应为准；身份来自 `App.jsx` 顶部选择器（1–5）。

## In scope

- 复用 REQ-019 的 `member_preference` 表，新增 `kind = 'submission'` 的读写；**不新增迁移**。
- `PUT /api/trips/{tripId}/preferences/submission`：请求体 `{"noPreference":false|true}`，响应 `{"status":"ready","noPreference":false|true,"submittedAt":"<ISO-8601 +08:00>"}`（无偏好时另带 `defaults`）。
- `GET /api/trips/{tripId}/preferences/readiness`：返回 `{"members":[{"userId","displayName","status","noPreference","submittedAt"}],"readyCount","memberCount","allReady"}`，全员、按 `userId` 升序。
- `GET /api/trips/{tripId}/preferences/effective`：返回**仅 ready 成员**的生成侧投影；`noPreference=true` 成员的个人值为空并带 `defaults`；pending 成员不出现。
- 空提交判定：`noPreference=false` 且四类偏好全无 → `400 PREFERENCE_EMPTY`（D7）。
- 错误码：新增 `PREFERENCE_EMPTY`(400)、`INTERNAL_ERROR`(500)；复用 `USER_REQUIRED` / `NOT_A_MEMBER` / `TRIP_NOT_FOUND` / `INVALID_REQUEST`。
- 偏好页的提交段：提交按钮 + 无偏好开关 + 就绪 pill + 失败错误条 + 空提交前置提示；成员页（节点 7）就绪环与三种 pill 的数据来源。
- 后端接口测试（行数恒 1、失败零写入、投影只含 ready 成员、保存不等于提交的写前后断言）+ 前端构建与浏览器观察。

## Out of scope

- 兴趣段（US-019）、必做项段（US-020）、预算段（US-024）：端点、payload 与保存交互均不改；本需求只**读**它们的 payload。
- 约束类偏好（`kind='constraint'`）：另一条故事；本需求在空提交判定与投影中必须容忍该 kind 缺失，返回 `null`。
- 撤销提交 / 退回 pending / 提交历史：AC 未要求，本需求只有 `pending → ready` 单向。
- 就绪后的失效与重生成（保存改动后草稿过期）：属 US-031/US-037，本需求明确**不**撤销就绪（D10）。
- 主线生成本身：`effective` 只提供输入；「全员就绪 + 主线已确认 + …」的组合门控属 US-031，`allReady` 只报「全员已提交」。
- 组织者代他人提交、催办/提醒、通知（邮件、推送）、就绪变更的实时推送。
- 默认画像的可配置化（交通方式选项、节奏选项）：本需求固定 `walking` + `standard`。
- 真实鉴权：`X-User-Id` 直接信任。
- 新表、新迁移、新组件库、新路由库。

## Contract

### 三个端点

| 方法 | 路径 | 请求体 | 成功响应 |
|---|---|---|---|
| PUT | `/api/trips/{tripId}/preferences/submission` | `{"noPreference": false}` | `{"status":"ready","noPreference":false,"submittedAt":"2026-11-15T10:12:00+08:00"}` |
| PUT | 同上 | `{"noPreference": true}` | `{"status":"ready","noPreference":true,"submittedAt":"...","defaults":{"transport":"walking","pace":"standard"}}` |
| GET | `/api/trips/{tripId}/preferences/readiness` | — | `{"members":[{"userId":1,"displayName":"Alice","status":"ready","noPreference":false,"submittedAt":"..."},{"userId":2,"displayName":"Ben","status":"pending","noPreference":null,"submittedAt":null}],"readyCount":1,"memberCount":4,"allReady":false}` |
| GET | `/api/trips/{tripId}/preferences/effective` | — | `{"members":[{"userId":1,"status":"ready","noPreference":false,"interests":["Art"],"mustDos":[{"id":"…","activity":"…","location":"…","time":null}],"budget":null,"constraints":null,"defaults":null},{"userId":4,"status":"ready","noPreference":true,"interests":[],"mustDos":[],"budget":null,"constraints":null,"defaults":{"transport":"walking","pace":"standard"}}]}` |

### 落库形状（`member_preference`，`kind='submission'`）

```json
{"status":"ready","noPreference":false,"submittedAt":"2026-11-15T10:12:00+08:00"}
{"status":"ready","noPreference":true,"submittedAt":"2026-11-15T10:12:00+08:00","defaults":{"transport":"walking","pace":"standard"}}
```

- 单行单对象，UNIQUE(`trip_id`,`user_id`,`kind`) + `INSERT ... ON CONFLICT DO UPDATE`，行数恒 1。
- **pending 就是没有这一行**；不存在「空提交态」行。
- `submittedAt` 由服务端生成，`Asia/Singapore` 偏移的 ISO-8601；请求体里即使带同名字段也忽略。
- payload 里的 `submittedAt` 是读契约的权威字段；表内 `updated_at` 仍是既有 housekeeping 列（UTC），两者不要求相等。

### 校验顺序（固定，任一步失败零写入）

1. `X-User-Id` 存在、为整数、指向已 seed 用户 → 否则 `401 USER_REQUIRED`
2. `tripId` 存在 → 否则 `404 TRIP_NOT_FOUND`
3. 调用者是该 trip 成员 → 否则 `403 NOT_A_MEMBER`
4. body 是 JSON 对象（非数组、非标量、非非法 JSON） → 否则 `400 INVALID_REQUEST`
5. `noPreference` 键存在 → 否则 `400 INVALID_REQUEST`
6. `noPreference` 是布尔 → 否则 `400 INVALID_REQUEST`
7. `noPreference=false` 且该成员四类偏好全无 → `400 PREFERENCE_EMPTY`
8. 写库（upsert）→ 失败 `500 INTERNAL_ERROR`

### 「四类偏好全无」的判定口径（D7）

| kind | 「无」的判定 |
|---|---|
| `interest` | 无行，或 payload 解析后 `codes` 为空数组 |
| `must_do` | 无行，或 payload 解析后 `items` 为空数组 |
| `budget` | 无行，或 payload 解析后不含 `amount` 键（即清除态的 `{}`） |
| `constraint` | 无行（该 kind 尚未实现；有行且非空即算「有」） |

四类**同时**为「无」才拒绝；只要有一类有内容就允许提交。

### `effective` 投影规则（D9）

- 只包含 `status = ready` 的成员；pending 成员**不出现**。
- `noPreference=false`：`interests` 取兴趣 payload 的 label 集合（空为 `[]`）、`mustDos` 取必做项 `items`（空为 `[]`）、`budget` 取预算对象或 `null`、`constraints` 为 `null`、`defaults` 为 `null`。
- `noPreference=true`：`interests=[]`、`mustDos=[]`、`budget=null`、`constraints=null`、`defaults={"transport":"walking","pace":"standard"}`，且**不读**该成员任何个人偏好行。
- 只读：不写库、不刷新 `updated_at`、不改 `submittedAt`。

## Constraints

- **技术栈**：Spring Boot 3.5 / Java 21 / `JdbcTemplate`（无 ORM）/ SQLite / Flyway；前端 React + Vite，沿用 hash 路由、`api.js`、`app.css`，不新增依赖。
- **存储**：复用 `member_preference`（`kind='submission'`，payload 为单个对象）；`V4` 由 REQ-019 建立，本需求**不新增迁移**；合入顺序硬前置：`V4` 与前三段（兴趣/必做项/预算）必须已在 main。
- **状态机**：`pending`（无行）→ `ready`（有行）；单向，无撤销。
- **默认画像**：`transport=walking`、`pace=standard`，写进 payload 的 `defaults`，不可配置。
- **时间**：`submittedAt` 为 `Asia/Singapore` 偏移的 ISO-8601，服务端生成。
- **响应风格**：成功裸 DTO，失败 `{"code","message"}`；错误 advice 与 REQ-019/020/024 同在 preference 包；500 需显式映射为 `INTERNAL_ERROR`。
- **身份**：`X-User-Id`（整数），不引入 `X-Member-Id`。
- **页面**：与前三段同页 `#/trips/{tripId}/preferences`；提交是**页面级显式动作**，与兴趣段（显式保存）、必做项段（动作即保存）、预算段（段内显式保存）互不代劳。
- **夹具**：用户与 trip 来自 `acceptance-test-fixtures.md`；US-026/US-027 的行为样例由本条目场景表补充，是否回填夹具见 OQ-9。
- **文档语言**：本需求 P1 产物用中文，标识符与命令保留原文。
