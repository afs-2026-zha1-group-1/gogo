## Intent

User rulings, 2026-11-15: budget clearing requires a confirmation dialog. Opening,
cancelling or dismissing it sends no request and preserves saved values and input;
Confirm sends the existing `{"amount":null}` PUT, with saved state updated only on
success. Must-do deletion retains the same confirmation contract from REQ-020.
Unset and zero must be distinct; exact copy belongs to UI implementation. Entry
uses clearly labelled currency/major units, with currency-specific minor-unit
storage (40 SGD -> 4000; no hard-coded factor for JPY). No currency conversion or
cross-currency comparison here; US-031 owns that follow-up. Emily subsequently
approved the revised 53-scenario package on 2026-11-15 per separate explicit user
instruction; SA revised-contract review and remaining G1 conditions stay open.

让成员用「可选金额 + 币种 + 软/硬上限」表达自己的花费边界，并让这份边界成为主线生成的过滤输入。
三条 AC 各自钉住一个容易做错的地方：AC1 要真落库（reload 后仍在）、AC2 要**原地改**上限类型（不产生第二条）、
AC3 要**区分未设置与 0**（这是最容易用「空字符串当 0」糊过去的点）。三者都要求「单行单对象覆盖写 +
三字段联动校验」，不能靠前端默认值或整段重填实现。

## Actors and boundaries

- **身份来源**：`X-User-Id` 请求头，整数，指向 `app_user` 主键。缺失、非整数或指向未 seed 的用户 → `401 USER_REQUIRED`。
- **成员判定**：读写都要求调用者属于该 `tripId` 的 `trip_member`，否则 `403 NOT_A_MEMBER`；`tripId` 不存在 → `404 TRIP_NOT_FOUND`；判定顺序 identity → trip → membership，复用 `TripRepository.findUserId` / `isMember`。
- **写边界**：只能写 header 指定成员自己的 `kind='budget'` 记录；无「替他人设预算」的合法路径。
- **金额边界**：最小货币单位整数，非负；`SGD`/`CNY`/`USD`/`EUR` 两位小数、`JPY` 零位；超出 int32 视为非法。
- **读边界**：`GET` 返回全员明细（D10），前端只渲染自己那一段。
- **前端边界**：不做本地持久化与离线队列；状态以服务端返回为准；身份来自 `App.jsx` 顶部选择器（1–5）。

## In scope

- 复用 REQ-019 的 `member_preference` 表，新增 `kind = 'budget'` 的读写；**不新增迁移**。
- `GET /api/trips/{tripId}/preferences/budget`：返回 `{"members":[{"userId":1,"budget":{...}}|{"userId":2,"budget":null}]}`，按 `userId` 升序。
- `PUT /api/trips/{tripId}/preferences/budget`：请求体 `{"amount":4000,"currency":"SGD","limitType":"hard"}`，响应 `{"budget":{...}}`；`{"amount":null}` 表示清除，响应 `{"budget":null}`。
- 校验：`amount` 键必须存在；金额非负整数且不超 int32；三字段联动必填；币种白名单严格匹配；上限类型仅 `hard`/`soft`（D5–D9、D12）。
- 错误码：`BUDGET_AMOUNT_INVALID`、`BUDGET_FIELDS_INCOMPLETE`、`BUDGET_CURRENCY_NOT_ALLOWED`、`BUDGET_LIMIT_TYPE_INVALID`，并复用 `USER_REQUIRED` / `NOT_A_MEMBER` / `TRIP_NOT_FOUND` / `INVALID_REQUEST`。
- 偏好页的预算段：金额输入 + 币种下拉 + 硬/软选择器 + 「保存预算」按钮 + 清除；loading / 未设置 / 已设置 / 保存中 / 失败五类状态。
- 后端接口测试（含行数恒 1、`budget:null` 与 `amount:0` 可区分、跨成员隔离的写前后断言）+ 前端构建与浏览器观察。

## Out of scope

- 兴趣段（US-019）与必做项段（US-020）：端点、payload 与保存交互均不改。
- 约束类偏好（`kind='constraint'`）：另一条故事。
- 「我没有特别偏好」显式态（US-027）与就绪门控/提交（US-026）：保存预算不改变就绪状态。
- 偏好对比视图（`GET /preferences/summary` 的共同/差异）：计划中的端点，本轮不实现。
- 主线生成与「硬上限严格过滤」的执行（US-031/US-037）：本需求只提供数据，不消费。
- 多币种换算与汇率：只存币种代码与最小单位金额，不做跨币种比较。
- 成员摘要（参考图节点 7）展示他人预算：只读消费方，不在本需求渲染。
- 主线确认后锁定偏好：沿用 REQ-019 的 D4，仅测试上下文。
- 金额业务上限、币种扩展、预算历史版本：AC 未规定，记入 OQ。
- 真实鉴权：`X-User-Id` 直接信任。
- 新表、新迁移、新组件库、新路由库。

## Constraints

- **技术栈**：Spring Boot 3.5 / Java 21 / `JdbcTemplate`（无 ORM）/ SQLite / Flyway；前端 React + Vite，沿用 hash 路由、`api.js`、`app.css`，不新增依赖。
- **存储**：复用 `member_preference`（`kind='budget'`，payload 为**单个对象**）；`V4` 由 REQ-019 建立，本需求**不新增迁移**；合入顺序硬前置：`V4` 必须在 main。
- **金额**：最小货币单位整数；小数位 `SGD/CNY/USD/EUR = 2`、`JPY = 0`；负数/小数/超 int32 → `400 BUDGET_AMOUNT_INVALID`。
- **币种**：白名单 `{SGD, CNY, USD, EUR, JPY}`，严格大写三码，不做归一化。
- **上限类型**：`hard` / `soft`，小写。
- **响应风格**：成功裸 DTO，失败 `{"code","message"}`；错误 advice 与 REQ-019/020 同在 preference 包。
- **身份**：`X-User-Id`（整数），不引入 `X-Member-Id`。
- **页面**：与 US-019/US-020 同页 `#/trips/{tripId}/preferences`；预算段为**段内显式保存**，必做项段仍是动作即保存，兴趣段仍是显式保存（D4/D13）。
- **夹具**：用户与 trip 来自 `acceptance-test-fixtures.md`；US-024 的行为样例由本条目场景表补充，是否回填夹具见 OQ-11。
- **文档语言**：本需求 P1 产物用中文，标识符与命令保留原文。

## Affected capabilities

- **修改**已有能力 `preferences`（REQ-019 引入、REQ-020 已修改一次）：新增预算读写契约，并第三次修订其页面契约（新增预算段、明确三段三种写入时机）。
- **不改** `trips`（REQ-003）与 `invitations`（REQ-004）的契约；只读复用 `trip_member`、`trip`、`trip.main_plan_confirmed` 与成员判定。
- **不新增**迁移：与 REQ-004 的 `V3`、REQ-019 的 `V4` 均无编号竞争。
