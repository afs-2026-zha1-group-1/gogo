## Intent

让发起人一键为两个分组各生成一条合适的分开活动路线：输入是组成员偏好与已固定的
拆分边界，输出是「同起点、同终点、各自活动」的一对路线。这一对路线要么一起存在、
要么都不存在；生成期间草稿若已变化，迟到的结果作废。

## Actors and boundaries

- 生成权限 = 草稿发起人；成员/身份契约同 REQ-004/005。
- 边界归属：后端独占成对原子性与版本校验；**候选提供者是后端内部的可替换接口**
  （OQ-3 裁决：`BranchCandidateProvider` 接口 + MVP 固定夹具实现），不是外部服务，
  不引入网络依赖；前端不接触候选供给细节。
- 分组成员：本期由夹具供给（A = Alice+Ben，B = Chloe+Daniel）；分组移动作为
  草稿变更使 draft_version+1（OQ-5），移动控件本身为可选（见 Out of scope）。
- 路线存储：复用 `plan_node` 树（`branch_id` 区分分组分支，`parent_id` 预留已就位，
  DR-04），不新建路线表、不加列；草稿与路线的关联口径见 deep-dive B 链段。

## In scope

- 生成端点（`POST /api/trips/{tripId}/split-draft/routes:generate`，`X-Member-Id` 头，
  `{data,error}` 包封套）：校验草稿活跃 + 发起人 + 边界已保存 + 分组齐全 →
  按组调用候选提供者 → 组装两条路线（同出发/会合边界）→ **单事务成对保存** →
  保存前条件校验 draft_version（不符即 stale 拒绝）→ 成功后 draft_version+1。
- `BranchCandidateProvider` 接口与 MVP 夹具实现：A → National Gallery Singapore、
  B → Gardens by the Bay，含活动时长（60 分钟）与交通估算（A: 15/20，B: 20/20 分钟）
  及 buffer（10 分钟），供 REQ-007 校验复用。
- 失败语义：任一组生成失败 → 整对回滚，返回错误（`code = ROUTE_GENERATION_FAILED`），
  库中不存在可确认的半成品对。
- 过期语义：请求携带发起时 draft_version；落库前条件更新校验，不符 →
  `409 code = STALE_DRAFT_VERSION`，v2 状态不受影响。
- 路线读取：草稿详情返回成对路线（分组、活动、起终点、时长/交通/buffer 分解）。
- 前端生成屏幕（Screen 13 为呈现参考）：生成动作、成对结果、失败态、过期态、
  loading/empty/permission 态。
- 后端验收测试（成对原子、失败回滚、stale 拒绝三场景）。

## Out of scope

- 分组编辑/移动**控件**（issue Design scope 明示可选）：本期分组由夹具供给，
  不实现前端移动 UI；但后端分组变更→版本递增的语义必须成立（stale 测试以接口/夹具构造）。
- 真实候选供给（LLM/景点库/打分）：R2；本期 MVP 固定夹具，接口留缝。
- 路线确认（US-049）、草稿取消（US-050）；窗口校验（REQ-007）。
- 多轮生成反思、agent 编排（tech-stack-plan §7 口径）；真实认证。

## Scenarios and AC hints

| id | 场景 | 可观察结果 |
|---|---|---|
| S1 | 草稿含 A 组（Alice+Ben）、B 组（Chloe+Daniel），边界 City Hall MRT 09:30 → Merlion Park 11:30，发起人用 fake 候选生成 | `200`，恰好两条路线成对保存：A 访问 National Gallery Singapore、B 访问 Gardens by the Bay；两条均起于 City Hall MRT、终于 Merlion Park；draft_version 递增 |
| S2-N | A 组生成成功但 B 组生成失败（夹具构造提供者对 B 抛错） | 错误响应 `code = ROUTE_GENERATION_FAILED`；库中无该草稿的任何新路线（无可确认半成品对）；draft_version 不变 |
| S3-N | 为草稿 v1 启动生成，期间分组成员移动使草稿变 v2，v1 结果返回 | `409` 且 `code = STALE_DRAFT_VERSION`；v1 结果被丢弃，v2 状态不被覆盖 |
| S4-N | 边界未保存时生成 | `409` 且 `code = SPLIT_BOUNDARIES_REQUIRED`；无路线落库 |
| S5-N | 非发起人触发生成 | `403` 且 `code = NOT_SPLIT_INITIATOR`；无路线落库 |

错误码为稳定机器可读契约；message 为实现文本。S3-N 的「移动分组」在验收测试中
通过后端分组变更路径构造（不依赖可选 UI 控件）。

## Constraints

- 同 REQ-004 全部技术约束；成对保存用**单事务**（SQLite 单写者，池=1 天然串行，
  事务内完成两条路线写入 + 版本条件更新）。
- 候选提供者为进程内接口，MVP 实现读固定夹具值；不得引入外部网络调用（DR-07 口径）。
- 路线行写 `plan_node`：`branch_id` 标识分组分支（`split-a`/`split-b`，按 trip_id
  归属当前活跃草稿），`plan_version` = 草稿 main_plan_version；时长/交通/buffer
  存结构化 JSON 字段；重生成同事务先删旧对再写新对；不删除主线行。
- 前端增量引入新栈，greeting 页保持 JSX（用户 2026-11-15 裁决，同 REQ-004）。
