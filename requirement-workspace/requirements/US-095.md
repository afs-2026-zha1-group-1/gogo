## Intent

把分队窗口从「必须一对主线站」扩展为两种可保存形态：

| 形态 | 分头 | 会合 | 窗口 |
|---|---|---|---|
| `MIDDLE`（现有） | 选定主线站 `start_at` | 选定主线站 `start_at` | 会合开始 − 分头开始 |
| `FROM_START`（新增） | 第一站 `start_at` | 选定主线站 `start_at` | 会合开始 − 第一站开始 |

会合节点始终必选；不提供「到最后也不汇合」形态（用户 2026-11-18 裁定暂不做）。

## Actors and boundaries

- 发起人：保存边界、生成/重生成路线。
- 组织者：确认草稿；确认时服务端按保存的形态复算窗口与两条路线合计。
- 任意成员：读取路线、调整分组；改组不改变边界形态。
- 后端是唯一判定方：形态合法性、窗口正负、路线合计是否超窗均由服务端决定。

## In scope

1. 草稿文档新增 `splitMode`（`MIDDLE` / `FROM_START`），旧文档缺省时按两个站 id 推断为 `MIDDLE`，零迁移。
2. 保存边界接口接受 `departureStopId = null`（起点分头）；`reunionStopId` 仍必填，缺失返回 `400 BOUNDARY_NOT_IN_MAIN_PLAN`。
3. 窗口、详情、确认、生成、`plan_node` 起止时间统一按形态解析。
4. A 组路线：起点分头时从第一站开始，直到会合站（不含）；B 组仍用确定性夹具。
5. 边界页新增「行程起点」选项；会合站必须排在分头之后；起点分头时第一站不能作会合站。
6. 队伍路线图：起点分头时从第一站画出 fork，仍保留 join。
7. 路线卡与行程详情「我的方案」：分头文案显示「行程起点」，个人路线不再重复第一站。

## Out of scope

- 「到最后也不汇合」（`NO_REUNION`）——用户 2026-11-18 裁定先不做；后续如需要再单独立项。
- 按经纬度/路网自动计算路程；B 组仍用确定性夹具。
- 多日行程按天分段；窗口仍按当前单日主线模型计算。
- 新数据库迁移；`split_draft.document` JSON 列内扩展。
- 修改手动编辑路线（US-087）的站表结构；只沿用可空分头 id。

## Constraints

- 无新迁移：`splitMode` 只存在于 `split_draft.document` JSON，Jackson 缺字段为 null。
- 旧数据兼容：`splitMode` 为空且两个站 id 都存在 → `MIDDLE`；会合 id 为空 → 未保存边界或非法请求。
- 不新增错误码：沿用 `BOUNDARY_NOT_IN_MAIN_PLAN` / `NONPOSITIVE_SPLIT_WINDOW`。
- 夹具 B 组路线不按窗口缩放；超窗由现有校验拦截，不伪造可行。

## Affected capabilities

- `splits`：边界保存、草稿详情、路线生成、确认、窗口复算。
- 前端分队：边界页、分组与路线页、队伍路线图、确认页（文案沿用窗口）。
- 行程详情：个人路线时间线（`personal-route`）。

## Implementation notes (2026-11-18)

- 后端：`SplitMode`（MIDDLE/FROM_START）、`SplitBoundaries`；`saveBoundaries` / `generateRoutes` / `getDraftDetail` / `confirmDraft` 统一解析形态；`FixtureBranchCandidateProvider` 支持空分头；`plan_node` 起止时间随形态写入。
- 前端：`SplitDraftDetail.splitMode`、`BoundaryResult.splitMode`；边界页「行程起点」选项；路线图 `hasBoundaries`；路线卡与个人路线的起点文案。
- 后端 mock（2026-11-18 反馈修订）：`FROM_START` 不再按「先汇合再分开」造数——`FixtureBranchCandidateProvider` 在空分头时去掉 B 组的去程，B 只剩回程，其首个地点就是自己的活动（不再从主线首站出发）。
- 路线图（2026-11-18 反馈修订，第四次迭代）：`FROM_START` 无分头节点、无出发行，两条泳道各自以自己的首个地点开头（A = 主线首站活动，B = 自己的活动），同高、按阶段对齐（`branch-pair`），只在会合处汇合——既「一开始就不汇合」，也没有重复节点。`MIDDLE` 沿用 main 的去重：分头节点吸收 A 组首站活动（meta 追加「A 组活动 · N 分钟」），不再重复画一次。此前几版（B 去程独立占行、浮动旁注、泳道表头、两个同名出发节点）均已被反馈否定。
- 路线卡（2026-11-18 反馈修订）：新增共享行序 `route-rows.ts`（`cardRowOrder` / `hasEntryLeg`），按「legs 数 = steps 数 + 1」判定去程而非按组名硬编码；仅当首行仍是路程（旧草稿）时才渲染「从 <起点> 出发」的只读行，新数据下 B 卡直接以活动开头、卡头的出发地取自身首站；编辑卡与只读卡共用同一行序，只读卡原先「先所有站、再所有路程」的顺序错误一并修正。
- 验证：后端 `mvn test` 全绿；前端 `typecheck`、`test:unit`、`build` 全绿；隔离环境浏览器走通 起点分头→保存→分组→生成→确认。
