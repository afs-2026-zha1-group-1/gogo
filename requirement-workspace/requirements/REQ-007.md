## Intent

在确认拆分之前，给成员一个可信的时间答案：两条路线各自「活动 + 每一段交通 + buffer」
的总耗时是否都装得进拆分窗口。答案只有三种——通过、超窗（给出超多少）、缺输入
（指出缺什么）；后两种都意味着这对路线当前不可确认。

## Actors and boundaries

- 校验权限 = 任意行程成员（issue 角色 "As a trip member"）；身份契约同 REQ-004。
- 边界归属：后端独占耗时合计与可行性判定（纯函数式计算）；**不写数据库**
  （issue Required layers: Database No — Validate supplied snapshot）；
  前端只呈现分解与结论，不自行宣布可行。
- 输入 = 供给的快照：窗口分钟数 + 每条路线的活动时长、交通段列表、buffer；
  校验端点接受**显式快照 body**（OQ-N6）。The entry guard may read member/trip
  records; the calculator has no repository access and uses only the supplied
  snapshot, without reading stored routes. Frontend reads the member-only
  `GET /api/trips/{tripId}/split-draft` to assemble that snapshot.
- 「拦住整对确认」的本期语义：校验结论 `feasible=false`（超窗或缺输入）即整对
  不可确认；确认动作本身属 US-049（未实现），本期以校验结论为契约输出，
  不实现确认端点，也不持久化校验结果。

## In scope

- 校验端点（`POST /api/trips/{tripId}/split-draft/routes:check-timing`，
  `X-Member-Id` 头，`{data,error}` 包封套）：接受显式成对路线快照 body
  （windowMinutes + routes[2]，用户裁决 OQ-N6），逐条路线计算
  `total = 活动时长 + Σ交通段 + buffer`，与窗口比较；the calculator performs no
  database reads/writes; the authorized entry guard may read membership records.
- 结论契约：每条路线返回 `totalMinutes`、`windowMinutes`、`overrunMinutes`（超窗时）、
  `missingInputs`（缺输入时逐项列出）；整对 `feasible` 仅当两条路线均无超窗且无缺失。
- 缺输入语义：活动时长、任一交通段估算、buffer 缺失 → 该路线判为缺输入，
  整对 `feasible=false`；缺失不得呈现为通过（issue Design scope 明示）。
- 前端校验屏幕（Screen 14 为呈现参考）：两条路线的活动/交通/buffer 分解、
  通过态、超窗态（显示超出分钟数）、缺输入态（列出缺失项）、loading/empty/permission 态。
- 后端验收测试（通过/超窗/缺输入三态 + 纯计算无写库断言）；夹具用 120 分钟窗口，
  不写死演示时长。

## Out of scope

- 确认拆分（US-049）与取消草稿（US-050）：本期只输出校验结论，不实现确认/取消端点。
- 校验结果持久化、校验历史（Database: No）；交通估算的真实来源（地图/路径服务，R2）。
- 路线编辑、重新生成（REQ-006）；窗口本身的修改（REQ-005）。
- 单条路线独立放行：结论以「整对」为单位（issue AC2「blocking confirmation of the pair」）。

## Scenarios and AC hints

| id | 场景 | 可观察结果 |
|---|---|---|
| S1 | 窗口 120 分钟，A = 15+60+20+10、B = 20+60+20+10（buffer 各 10） | `200`，A total = 105、B total = 110，均 ≤ 120；整对 `feasible = true` |
| S2-N | A 的最后一段交通改为 40 分钟（其余不变） | `200`，A total = 125、`overrunMinutes = 5`；整对 `feasible = false`（拦住整对确认）；B 仍单独显示 110 通过 |
| S3-N | A 的活动时长或末段交通估算缺失 | `200`，A `missingInputs` 列出缺失项；整对 `feasible = false`；不得显示为通过 |
| S4-N | 非成员发起校验 | `403` 且 `code = NOT_A_MEMBER`；不返回路线数据 |
| S5-N | 快照为空/路线数不为 2 | `400` 且 `code = INVALID_ROUTE_PAIR`；不产生结论 |
| S6-N | Missing/globally unknown member id; known member with unknown trip; known outsider | Respectively `401 MEMBER_REQUIRED`, `404 TRIP_NOT_FOUND`, `403 NOT_A_MEMBER`; `data=null`, calculator not invoked |

错误码为稳定机器可读契约；message 为实现文本。S2-N/S3-N 的 HTTP 状态为 200 +
`feasible=false`（校验成功执行、结论为不可行），与请求非法（4xx）区分。
算式中的交通段数值来自夹具（A: 15/20，B: 20/20），校验逻辑不得写死这些值。

## Constraints

- 同 REQ-004 技术约束（JdbcClient 无 ORM、SQLite 三铁律、Flyway 独占、
  `{data,error}` 包封套、`X-Member-Id`）；本 REQ 不新增迁移、不写库。
- 时间粒度 = 分钟（整数）；窗口与时长均为夹具供给的显式数值，
  不得从演示截图推断固定时长（issue Design scope 明示）。
- 纯计算：校验用例层不依赖 Repository（零读零写，用户裁决显式快照 body）。
- 前端增量引入新栈，greeting 页保持 JSX（用户 2026-11-15 裁决，同 REQ-004）。
