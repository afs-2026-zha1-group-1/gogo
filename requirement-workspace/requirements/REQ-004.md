## Intent

让一个行程在主线确认之后，能够以「唯一草稿」的方式开启拆分规划：任何成员发起一次，
其他人再发起只会收到冲突，而不是产生互相竞争的多份拆分。草稿从创建起就锁定所依据的
已确认主线版本，为后续边界选择与路线生成提供稳定载体。

## Actors and boundaries

- 身份为**脚手架级轻量身份**（tech-stack-plan DR-05）：邀请码 + 昵称加入，
  `X-Member-Id` 头传递 `trip_member.id`，MVP 不做签名校验，不得描述为安全控制。
- All five split endpoints check identity, then trip existence, then membership.
  Missing/globally unknown member id: `401 MEMBER_REQUIRED`; known member with
  unknown trip: `404 TRIP_NOT_FOUND`; known outsider: `403 NOT_A_MEMBER`.
  Rejections return `data=null` without private values. Timing entry guards may
  read membership data; only the timing calculator is database-free.
- 发起权限 = 任意行程成员（US-038 正文角色 "As a trip member"，AC 由成员 Ben 发起；
  Alice 是 organizer 但同样受唯一性约束）。非成员与缺失/未知身份被拒绝。
- 边界归属：后端拥有 `trip` / `trip_member` / `member_preference` / `plan_node` 四表（含 trip 内草稿 JSON 文档）与发起端点，
  独占成员资格、主线确认前置、活跃唯一性三项判定；前端只呈现发起动作与
  loading / error / empty / permission 状态，不自行判定唯一性或确认状态。
- 「已确认主线 v1」本期由**种子夹具**供给（迁移内种子数据），不依赖 US-037 实现；
  确认状态的读取契约按 tech-stack-plan 的 `trip.plan_version` + `trip_member.plan_ack_version`
  模式表达，未来 US-037 落地时复用同一契约（对齐事项见 OQ-N1）。
- **「主线已确认」判定谓词（本轮裁决沿用）**：全部成员的 `plan_ack_version` 均等于
  `trip.plan_version` 时视为已确认；任一成员未 ack 当前版本即未确认。夹具两态按此构造：
  主线 v1 已确认 = 4 名成员均 ack v1；未确认态 = 至少一名成员 ack 落后。

## In scope

- Flyway 迁移按 tech-stack-plan §5 建 `trip`、`trip_member`、`member_preference`、
  `plan_node` 四表（含 `branch_id` 默认 `main`、`parent_id` 自引用预留；
  `member_preference` 本链无需种子）。**不新增第 5 表、不加
  plan_node 列**（用户 2026-11-15 裁决「按照 tech-stack-plan 来」）：拆分草稿以
  JSON 文档存于 `trip.split_draft`（可空 TEXT 列，V2 迁移内唯一 schema 扩展）；
  活跃唯一由「每 trip 至多一份草稿文档 + 条件更新」保证，撞车即冲突；
  文档字段明细见 deep-dive B 链段。
- 种子夹具：Singapore Friends Day 行程、本行程 4 名成员（Alice=owner，Ben/Chloe/Daniel=member）
  + Eve 为另一行程的种子成员（非本行程成员）、已确认主线 v1（含 City Hall MRT scheduled end 09:30、Merlion Park
  scheduled start 11:30 / scheduled end 12:00 等 stop，供后续 REQ 复用）。
- 发起拆分草稿端点（`POST /api/trips/{tripId}/split-draft`，`X-Member-Id` 头，
  `{data,error}` 包封套）：成员资格校验 → 主线确认前置校验 → 活跃唯一性强制 →
  创建草稿（记录发起人、关联主线版本、草稿版本从 1 起）。
- Member-only `GET /api/trips/{tripId}/split-draft` returns a consistent saved
  snapshot for refresh/polling: initiator, main/draft versions, status, groups,
  timestamps, main-plan stop options, nullable boundary ids/times/window, and
  route pair (empty before generation). Existing trip without an active draft:
  `200 {data:null,error:null}`. Reads never mutate data or increment versions;
  non-initiator members may read. See delta D1-D5-N and fixture detail requests.
- 并发控制按 tech-stack-plan §7 铁律：条件更新（`UPDATE trip SET split_draft=…
  WHERE id=? AND 草稿状态匹配`，影响行数 0 即冲突），冲突返回 409；
  落地 SQLite 三铁律配置（`maximum-pool-size=1`、WAL、`busy_timeout=5000`、`foreign_keys=on`）。
- 前端发起拆分屏幕（Screen 11 为呈现参考）：发起动作、成功态、冲突态、主线未确认态、
  无权限态、loading/empty 态；前端**增量引入新栈**（用户 2026-11-15 裁决）：
  TypeScript + Ant Design + TanStack Query + React Router，B 链新页面用新栈，
  现有 greeting 页保持 JSX 不动。
- 后端验收测试（含并发场景）与验证文档更新；`acceptance-test-fixtures.md` B 链段扩展。

## Scenarios and AC hints

| id | 场景 | 可观察结果 |
|---|---|---|
| S1 | 主线 v1 已确认、无活跃草稿，Ben（成员）于 09:00 发起 | `201`，返回草稿：关联主线版本 = 1、发起人 = Ben、草稿版本 = 1、状态活跃；库中恰有一条该行程的活跃草稿 |
| S2 | Alice 与 Ben 并发发起同一行程的拆分 | 最多一个活跃草稿；成功者 `201`，另一请求 `409` 且 `code = SPLIT_DRAFT_CONFLICT`；库中活跃草稿数 = 1 |
| S3-N | 主线未确认（夹具构造：至少一名成员 plan_ack_version 落后于 trip.plan_version）时成员发起 | `409` 且 `code = MAIN_PLAN_NOT_CONFIRMED`；不创建草稿 |
| S4-N | Eve（非成员）发起 | `403` 且 `code = NOT_A_MEMBER`；不创建草稿，响应不含行程私有数据 |
| S5-N | Missing header or globally nonexistent member id (not a known outsider) | `401 MEMBER_REQUIRED`; no draft created |
| S6-N | Known member id with nonexistent tripId | `404 TRIP_NOT_FOUND` |
| S7 | 已存在活跃草稿时再次发起（串行重复） | `409` 且 `code = SPLIT_DRAFT_CONFLICT`；原草稿不变 |

错误码为稳定机器可读契约（沿用 REQ-003 草稿的 `code` 模式与 tech-stack-plan 的
`{data,error}` 包封套）；人类可读 message 为实现文本，不构成契约。
HTTP 状态选择：冲突/前置状态不满足 = 409（tech-stack-plan §10 版本冲突先例），
成员拒绝 = 403、身份缺失 = 401、未知行程 = 404。

说明：AC 中「09:00」为夹具时间语境，story 允许 "before or during travel"，
发起不做时刻校验；「no split has been used」按 issue Design scope 收敛为
「无活跃草稿」判定，取消后的替换语义归 US-050。

## Constraints

- Java 21 + Spring Boot 3.5.x；持久化 `JdbcClient` + `record` 手写 SQL，无 ORM
  （tech-stack-plan DR-02；注意与 REQ-001/002 现用 `JdbcTemplate` 的差异，
  新包按方案执行，不回改 greeting）。
- SQLite 单文件 + WAL + 池=1 + `busy_timeout=5000` + `foreign_keys=on`（DR-03，§7 三铁律）。
- schema 变更 Flyway 独占；已发布迁移不可改，一律新增 `V{n+1}`（DR-09）。
  当前库已有 `V1__create_greeting.sql`，B 链基础从 V2 起编号；与 REQ-003 计划中的
  V2 存在编号/表重叠，属待对齐事项（OQ-N1），不在本 REQ 内裁决。
- 时间一律 TEXT（ISO-8601 UTC）；夹具语境 Asia/Singapore (+08:00)，
  09:30 本地 = 01:30Z，换算在夹具中显式给出。
- API 统一 `{data,error}` 包封套、`/api` 前缀、`X-Member-Id` 头（§6）。
- 前端增量引入 TypeScript + Ant Design + TanStack Query + React Router（§3）；
  现有 greeting 页保持 JSX 不动（用户 2026-11-15 裁决，vite 原生支持混编）。
- 仓库文档产物依用户偏好用中文撰写。
