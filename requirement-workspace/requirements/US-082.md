## Intent

统一并修正前端返回与登录回跳目标：入会成功直达被接受的行程，分队与主线方案返回该行程详情并恢复行程上下文，未登录深链在登录后回到原页，登录/注册内部链接统一走 Router 路由。

## Actors and boundaries

- 入会成功页的「进入行程」只在接受成功后出现；预览态仍只显示公开信息，不暴露行程 id。
- 登录回跳只接受同源站内路径；`pendingInvite` 优先于普通回跳。
- 成员页与创建页返回由 US-071 拥有，本 change 不重复实现，只在其合并后回归。
- 两套路由并存：登录页同时被 Router `/login` 与 hash `#/login` 复用，因此回跳实现不得依赖 Router hook。

## In scope

- `Join.tsx`：joined 状态保存 `AcceptResult.tripId`，主按钮「进入行程」→ `#/trips/<id>`。
- `screen-start.tsx`：分队首页返回 `/#/trips/<id>`。
- `MainPlan.tsx`：主线方案返回 `#/trips/<id>`。
- `RequireAuth.tsx` + `LoginPage.tsx`：`?next=` 保留原深链并在登录后恢复，非法值回默认路由。
- `RegisterPage.tsx`、`LoginPage.tsx`、`Join.tsx`：登录/注册内部链接统一为 `/login`、`/register`。

## Out of scope

- 行程 tab 恒落 `#/trips`、成员名册返回、创建页返回：US-071 已拥有（G1 Pass）。
- `App.tsx` 的扫描路由与关闭恢复：US-067 的 active surface。
- 后端接口、会话、CSRF、数据库、依赖：均不变。
- 移除 `#/login`、`#/register` 既有 hash 入口：本 change 保留，另立清理。

## Scenarios and AC hints

| id | Scenario | Observable outcome |
|---|---|---|
| AC1 | 受邀访客接受邀请成功 | 主按钮为「进入行程」，点击后打开 `#/trips/<id>`；「返回首页」仍可用 |
| AC2 | 成员页空名单或错误态点击「返回行程」 | 由 US-071 交付：回到 `#/trips/<id>` |
| AC3 | 从首页进入创建页并返回 | 由 US-071 交付：回到 `#/trips` |
| AC4 | 从行程详情进入 `/trips/<id>/split` 后返回 | 回到 `#/trips/<id>`，成员/分队入口仍解析该行程 |
| AC4-N | 直接打开 `/trips/<id>/split` 后返回 | 回到 `#/trips/<id>`，不落首页 |
| AC5 | 未登录直接打开 `/trips/<id>/split/boundaries` 并登录 | 登录后回到该边界页 |
| AC5-N | `next` 为跨源或非站内路径 | 登录后回默认路由，不打开外部地址 |
| AC6 | 登录页「创建账号」、注册页返回/「去登录」 | 分别打开 `/register`、`/login` |
| AC7 | 从行程详情进入主线方案后返回 | 回到该行程详情 |

## Constraints

- 无新端点、无迁移、无新依赖；只改前端跳转。
- 返回目标显式声明，不使用 `navigate(-1)`/`history.back()`。
- 回跳值必须同源且以单个 `/` 开头，防止开放重定向。
- 与 US-071、US-067 的共享文件按各自 G1 已确认的所有权处理，不并发改写。
