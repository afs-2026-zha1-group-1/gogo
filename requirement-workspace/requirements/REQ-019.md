## Intent

让成员用固定的 7 项兴趣表达偏好，系统落一份"唯一化"的兴趣集合供后续方案生成使用；同时对绕过前端直接提交的非法值做出明确拒绝，且不破坏已有数据。写入必须真落库并可回读——这是 AC1「reload 后仍可见」与 AC2「已保存不变」的共同前提。

## Actors and boundaries

- **身份来源**：`X-User-Id` 请求头，整数，指向 `app_user` 主键（与 REQ-003 的 trip 接口同一套脚手架身份）。缺失或指向未 seed 的用户 → `401 USER_REQUIRED`。
- **成员判定**：写与读都要求调用者属于该 `tripId` 的 `trip_member`，否则 `403 NOT_A_MEMBER`；`tripId` 不存在 → `404 TRIP_NOT_FOUND`。判定逻辑复用 `TripRepository.isMember`，本需求不重写。
- **写边界**：只能写 header 指定成员自己的记录。没有"编辑他人偏好"的合法路径，因此**无跨成员写入分支**。
- **读边界**：`GET` 返回全员偏好明细（D8）；前端只渲染当前用户那一条。
- **前端边界**：不做本地持久化；页面状态以服务端返回为准。身份由 `App.jsx` 顶部已有的 demo 身份选择器提供（用户 1–5）。

## In scope

- Flyway 迁移 `V4`：新增 `member_preference` 表（`kind` 本需求只用 `interest`）。
- `PUT /api/trips/{tripId}/preferences`：以 `X-User-Id` 定位成员，幂等覆盖其 `interests`。
- `GET /api/trips/{tripId}/preferences`：返回封套内的全员偏好明细，本需求只填 `interests`。
- 7 项预定义兴趣常量（小写 code + 规范化 label）与严格校验。
- 统一错误码：`USER_REQUIRED`（401）、`NOT_A_MEMBER`（403）、`TRIP_NOT_FOUND`（404）、`INTEREST_NOT_ALLOWED`（400）、`INVALID_REQUEST`（400）。
- 偏好页：7 个选择的 chip、loading / empty / error / saving 四态、400 的内联错误。
- 后端接口测试（含 payload 写前后对比）+ 前端构建与浏览器观察。

## Out of scope

- 必做项、约束、预算三类偏好（`payload` 的其它 kind）。
- "我没有特别偏好"显式态（US-027）与就绪门控（US-026）。
- 偏好对比、方案生成与主线确认（US-031 及后续）。
- 邀请与加入（US-008/US-010，REQ-004）、成员列表（US-013）、行程编辑删除（REQ-003 非目标）。
- 真实鉴权/授权：`X-User-Id` 直接信任，不引入密码、会话或 token。
- `tag` 表与 `/api/tags` 字典端点（留给 M2.5 的 24 码词表）。
- 主线确认后锁定偏好（D4 裁定不实现）。
- 兴趣目录维护后台、i18n、分页、排序自定义。

## Constraints

- **技术栈**：Spring Boot 3.5 / Java 21 / `JdbcTemplate`（无 ORM）/ SQLite / Flyway；前端 React + Vite，**沿用现有 hash 路由、`api.js`、`app.css`，不新增组件库**（D5）。
- **复用既有 schema**：`app_user`、`trip`、`trip_member` 由 `V2__create_trip.sql` 建立（REQ-003），本需求只新增 `member_preference`（V4，D1/D7）。
- **响应风格**：成功返回裸 DTO，失败返回 `{"code","message"}`，与 `TripController` / `TripErrorAdvice` 一致（D10）。
- **身份**：`X-User-Id`（D10），不引入 `X-Member-Id`。
- **迁移顺序**：`V4` 合入前必须确认 `V3`（REQ-004 邀请）已在 main，否则 Flyway 会因 out-of-order 失败；若顺序无法保证，按合入时的下一可用版本调整，禁止制造乱序。
- **值域**：传输值 = 7 个 label 的精确字符串；存储值 = 对应小写 code；不做大小写与空白归一化（D2/D3）。
- **夹具**：`acceptance-test-fixtures.md` 提供用户与 trip；本需求的行为样例由本条目的场景表补充（是否把 US-019 用例补进该文件见 OQ-15）。
- **文档语言**：本需求 P1 产物用中文，标识符与命令保留原文。

## Affected capabilities

- **新增**能力 `preferences`（Living Spec 由本变更的 delta 在归档阶段建立）。
- **不改** `trips`（REQ-003）与 `greeting` 的行为契约；仅复用前者的表与成员判定。
- 与 REQ-004（邀请）共享迁移序列：`V3` 归 REQ-004，本需求用 `V4`。
