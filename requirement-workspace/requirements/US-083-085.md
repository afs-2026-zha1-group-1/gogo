## 故事与验收标准（摘自看板最新正文，2026-11-17）

### US-083 在行程页面直接查看主线和打开邀请
所需部分：前端是；后端是（读取现有行程、方案、成员和邀请）；数据库是（读取现有数据）。
- AC1 成员打开详情：行程名称、日期、目的地以紧凑两行摘要显示，不再显示重复的行程信息区块。
- AC2 页面依次显示：行程摘要、倒计时、同行成员、"我的方案"。
- AC3 已有方案：直接显示该行程的活动和时间，无需点击"查看主线方案"；尚无方案显示无方案状态，不显示其他行程的路线。
- AC4 不显示独立"分队规划"区块，也不显示"审阅并确认主线"按钮；主线确认仍遵循 US-081。
- AC5 组织者点击右上角邀请图标：可查看该行程邀请二维码和链接，并能返回原行程。
- AC6 当前用户无权分享邀请：打开邀请入口不泄露邀请链接，显示相应权限或不可用状态。

### US-084 分队确认后在行程详情查看个人路线
- AC1 组织者确认分队且校验成功：确认完成后返回当前行程的行程详情。
- AC2 分队已确认且成员已分配到某条路线：成员打开详情，"我的方案"显示该成员所属分队的活动及其时间，并保留分队前后的共同活动。
- AC3 不同成员被分配到不同路线：各自查看自己的详情时各见所属路线，不把另一组路线当作自己的方案。
- AC4 成员未分配到任何分队：查看详情时不显示其他分队的路线作为其个人方案。
- AC5 分队确认未成功或草稿被取消：不将未确认路线显示为已确认的个人方案。

### US-085 查看当前活动倒计时和接下来的活动
- AC1 行程尚未开始：显示距离行程出发的实时倒计时。
- AC2 当前时间处于成员方案某个活动时间段内：显示该活动结束前的剩余时间以及该成员的下一站，并持续更新倒计时。
- AC3 当前时间处于两个活动之间：显示距离下一活动开始的倒计时及下一站。
- AC4 分队已确认且成员有个人路线：倒计时和下一站以该成员所属路线及共同活动为准，不使用其他分队的路线。
- AC5 当天没有活动安排或当前活动后没有下一站：显示相应无安排或无下一站状态，不显示其他日期或行程的活动。
- AC6 倒计时到达活动边界：页面按当前时间切换到下一活动或相应状态，且倒计时不显示负数。
- 吸收原 US-078（Iteration 2 / Could）的"接下来的活动详情"三条：
  - N1 有当天路线：下一项显示活动名称、时间、地址、小组及根据已知交通时间计算的建议出发时间。
  - N2 地址或交通时间未知：缺失信息显示为待确认，不伪造出发时间。
  - N3 当天没有后续活动：显示没有更多活动。

- R3 分队依赖：读真实已确认分队 `GET /api/trips/{id}/split-draft`（确认后行保留、status=confirmed）。US-049/050 已在 main（G3 归档 2026-11-17），**不建种子夹具读模型、不等待**。
- R4 邀请入口：独立全屏页 `#/trips/{id}/invitation`（无底部导航，对齐参考图2）；TripDetails 顶栏右上改人形邀请图标；非组织者显示权限/不可用态、不泄露链接。参考图2 中"链接有效期/撤销/微信"属 US-008/012 原型演示 extras，不在 US-083 AC 内且后端无 expiry/revoke 列，本 change 不实现（登记为偏离 D-1）。
- R5 详情移除（仅新版概览态，R9）：重复"行程信息"列表区块、"旅行偏好"卡、内嵌 InvitationPanel 区、"分队规划"区、"审阅并确认主线"按钮、"查看主线方案"链接。旧版详情页（无方案时）保留上述既有区块。主线确认仍走 US-081（MainPlan 页保留作确认面，不删）。US-072 的"查看主线方案"入口 requirement 由本 change MODIFIED 取代（有方案时内嵌时间轴替代链接；无方案时旧版链接保留）。
- R6 "我的方案"数据源：split status=confirmed 且成员在 groups 中 → 该成员所属组个人路线；否则 main-plan stops；无主线方案 → 整页回退旧版详情页（R9 修订，不显示其他行程路线）。
- R7 倒计时口径：未出发=距 trip 出发（startDate 本地 00:00）显示 `N 天 HH:MM:SS`；活动中=距该活动结束+下一站；活动间=距下一活动开始；split confirmed 改用我组 ISO 时间戳+共同活动；到边界按当前时间切换、不显负数；每秒 tick；时区=设备本地（MVP 假设，G1 确认）。
- R8 下一站详情：名称/时间/地址/小组+由 travelMinutes 推算的建议出发时间；地址或交通时间缺失=待确认、不伪造；无后续=没有更多活动。
- R9 页面分流（2026-11-17 用户裁决，修订 R6 第 3 条）：无主线方案时保留现有旧版详情页（行程信息/旅行偏好/内嵌邀请/查看主线方案入口）；有主线方案时才展示新版概览（紧凑摘要/倒计时/同行成员/我的方案）。旧版原样保留 main 实现（TripDetailsLegacy），新版拆为 TripOverview，TripDetails 作分流入口。

## 范围与数据源

- 前端组合现有读接口（后端预计零新增 schema/端点）：
  - `GET /api/trips/{id}`（trip 摘要/日期/组织者/mainPlanConfirmed）
  - `GET /api/trips/{id}/main-plan`（PlanResponse：confirmed/stale/stops[seq,name,startTime,endTime,travelMinutesToNext,interests]/costPerPersonCents；stop 时间为 HH:mm）
  - `GET /api/trips/{id}/split-draft`（SplitDraftDetail：status/groups/routes/mainPlanStops[ISO startAt/endAt]/departureAt/reunionAt/windowMinutes；null=无草稿）
  - `GET /api/trips/{id}/members`（成员名册/头像/组织者）
  - `GET /api/trips/{id}/main-plan/inputs`（readyCount/memberCount，供"偏好全部就绪"摘要）
- 个人路线派生（前端）：groups 中找含当前成员 id 的组 label → routes[label]（activityName/activityMinutes/travelLegsMinutes/bufferMinutes）+ mainPlanStops 共同段 + departureAt/reunionAt 拼带时间时间轴；只渲染我组。
- 主线时间拼接（pre-split）：stop HH:mm + trip.startDate 拼本地日期得活动起止。
- 邀请全屏页复用 InvitationPanel 内容（QR+链接+复制）+ appbar 返回 + 生效中 pill + 权限态。
