## Intent

在已验证登录之上补齐账号生命周期：登录后能看见"我是谁"、改自己的名字、退出；
未注册的人能自己创建账号。显示名是账号资料而非行程角色：改名只改
`app_user.display_name`，不改账号 id、成员关系、组织者身份或分组。退出只结束
当前会话，不删账号与数据。注册创建一条账号记录，不自动登录、不发验证邮件，
也不通过响应差异暴露邮箱是否已存在。

## Actors and boundaries

- **已登录账号**：`app_user` 一行 + `account_credential` 一行；资料端点只作用于
  会话主体自己的账号，请求体或路径都不接受目标账号 id。
- **会话**：Spring Security 服务端 HTTP session（REQ-008）。退出使当前会话失效；
  再次访问受保护面返回 401 `USER_REQUIRED` 或打开登录页。
- **公开面**：登录页、注册页、`POST /api/auth/register`、`GET /api/auth/csrf`、
  `GET /api/greeting`、`GET /api/invitations/{token}` 预览。注册页与登录页一样
  全屏、无底部 dock。
- **受保护面**：`GET/PATCH /api/auth/me`、`POST /api/auth/logout`、My Account
  页面及其余既有行程域。已登录访问登录/注册页返回仪表盘。
- **名称读取方**：成员列表、邀请身份、偏好、路线/分组标签、头像首字母等既有
  展示面读取最新 `display_name`；不持久化姓名副本，不做跨表同步写。

## In scope

- **注册（US-070）**：`POST /api/auth/register`，请求 `{email, name, password}`；
  公开但受 CSRF 保护；把 `app_user` 与 `account_credential` 写在**同一事务**；
  成功返回统一 `200 {"next":"login"}`，不建立会话、不返回账号投影。
  - 邮箱：trim + 小写 + 基础格式校验；唯一性由既有 `uk_account_credential_email`
    保证；重复邮箱（含并发）返回 `409 EMAIL_TAKEN`，不创建第二行；注册页弹窗
    明确提示"该邮箱已注册"并给出去登录/修改邮箱（用户 2026-11-17 指令，覆盖
    原"不披露"AC）。
  - 显示名：trim 后 1–30 字符。
  - 密码：6–72 字符（BCrypt 72 字节上限），无组合复杂度；只存 BCrypt 哈希。
  - 校验失败：`400` 扁平 `{code,message}`，可操作地指出字段规则，不创建账号。
- **登录页入口**：`#/login` 与 `/login` 增加"Create account"链接；注册页
  `#/register` 与 `/register` 提供返回登录。注册页按 UI 参考稿呈现品牌头部、
  返回按钮、名字/邮箱/密码/确认密码字段与"创建账号"主按钮；前端密码至少
  8 个字符，服务端仍接受 6–72 字节。
- **My Account（US-068）**：底部导航新增"我的"tab；页面展示当前显示名、邮箱、
  改名输入、保存动作与退出登录动作；无右上角资料快捷入口。
- **资料读/改（US-068）**：`GET /api/auth/me` 保持现有投影；新增
  `PATCH /api/auth/me`（`{name}`）返回更新后的 `{id,name,email}`；只改会话主体
  自己的账号；校验同显示名规则；CSRF 保护。
- **名称联动（US-068）**：改名成功后所有既有名称展示面与头像首字母使用最新名称；
  仪表盘问候使用账号名、不追加"组织者"；组织者徽标仍按行程角色展示。
- **退出登录（US-069）**：`POST /api/auth/logout`，受 CSRF 保护；使当前会话失效、
  清除 SecurityContext 与 cookie，返回 `204`。前端清除本地认证状态并打开登录页；
  失败时显示可恢复错误，不错误报告成功、不清空本地状态。
- **数据不变**：退出不删除账号、显示名、成员关系、组织者角色、分组或共享行程；
  注册新账号默认无成员关系。
- **测试与夹具**：新增/扩展 auth 后端测试、前端构建与浏览器走查；fixtures 追加
  §REQ-009。
- **Living Spec delta（P2）**：`auth` ADDED（注册、资料读写、退出）；`app-shell`
  MODIFIED（"我的"tab、右上角身份条移除、问候使用账号名、注册页全屏）。
- **无数据库迁移**：注册复用 `app_user`（`INTEGER PRIMARY KEY` 自增 rowid）与
  `account_credential`；改名复用 `app_user.display_name`。

## Out of scope

- 邮箱验证、找回/修改密码、SSO/社交登录、remember-me、多设备会话管理、账号
  删除/停用、管理员用户管理。
- 头像上传/裁剪；头像首字母是名称派生展示，不是上传资料。
- 扫码控件（US-067，issue #39）；仪表盘聚合（US-061）。
- 更改行程、邀请、主线方案、拆分的行为或权限规则；只读最新显示名。
- 注册/登录限流、账号锁定、验证码（部署关注点；见 Constraints 的例外）。
- 把 US-068 的看板卡所有权变更写进本需求；卡片交接是流程事项。

## Constraints

- 技术栈：Spring Boot 3.5 + `JdbcTemplate` + SQLite + Flyway；React + Vite；
  hash shell + React Router 双路由（`/login` 与 `#/login` 已并存，注册与"我的"
  沿用同一方式）。绑定计划 `docs/knowledge/architecture/tech-stack-plan.md`
  §2 写明"MVP 不做账号体系/注册登录"；REQ-008 已为登录记录偏差，本 change 在
  proposal 继续记录注册偏差，归档时按 `openspec/config.yaml` 收敛。
- 复用 REQ-008 的 `account_credential`（唯一邮箱、BCrypt）、`SecurityConfig`
  （session/CSRF/JSON 401）、`AccountResponse` 与扁平错误 `{code,message}`；
  不引入新的错误封装、ORM、JWT 或 Spring Session。
- 凭据策略（用户 2026-11-16 裁决）：邮箱 trim + 小写 + 基础格式；密码 6–72
  字节、无组合复杂度、BCrypt；显示名 trim 后 1–30 字符。2026-11-17 UI 参考稿
  追加：注册页密码至少 8 个字符并要求确认密码一致（客户端更严格；服务端
  6–72 字节契约不变）。客户端校验只是体验优化，服务端为准。
- 注册响应：新邮箱 `200 {"next":"login"}`；重复邮箱 `409 EMAIL_TAKEN`（扁平
  `{code,message}`），不创建第二行、不建立会话。注册页对两种结果分别弹出
  成功/重复提示。**偏差**：用户 2026-11-17 明确要求重复邮箱给出提示，覆盖
  US-070 原"不披露邮箱是否已注册"的隐私 AC；该偏差记录在 G1 addendum，接受
  邮箱枚举风险。
- 退出：`POST /api/auth/logout`，CSRF 保护，`204`；失效当前会话并清理 cookie；
  重复退出/无会话返回 401 `USER_REQUIRED`，前端按"已登出"处理但不宣称新成功。
- 资料更新：`PATCH /api/auth/me`，CSRF 保护，只作用于会话主体；返回更新后的
  `{id,name,email}`；不提供目标账号参数。
- 无新迁移：注册为 `app_user`（rowid 自增）+ `account_credential` 同事务插入；
  并发重复由唯一索引兜底并映射为通用成功。
- UI：沿用 430px 仪表盘壳与现有 token；底部导航新增"我的"tab；移除
  `AccountBar` 右上角身份条；注册页/登录页全屏无 dock；My Account 在壳内带 dock。
- 安全基线：密码不写日志/不返回；注册/退出/改名均 CSRF；受保护面 401
  `USER_REQUIRED`；限流与账号锁定作为部署例外记录，不在本 change 实现。
