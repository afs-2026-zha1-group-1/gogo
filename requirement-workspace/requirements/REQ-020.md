## Intent

让成员用「活动 + 地点/固定时间」表达不可让步的体验，并把这份清单作为后续方案生成的硬输入。可验证边界由三条 AC 钉死：保存必须真落库（reload 后仍在）、修改必须**原地生效**（不产生第二条）、删除必须只影响自己。三件事都要求条目有稳定标识与逐成员隔离，不能靠前端数组或整段重填糊过去。

## Actors and boundaries

- **身份来源**：`X-User-Id` 请求头，整数，指向 `app_user` 主键。缺失或指向未 seed 的用户 → `401 USER_REQUIRED`。
- **成员判定**：读写都要求调用者属于该 `tripId` 的 `trip_member`，否则 `403 NOT_A_MEMBER`；`tripId` 不存在 → `404 TRIP_NOT_FOUND`；判定顺序 identity → trip → membership，复用 `TripRepository.findUserId` / `isMember`。
- **写边界**：只能写 header 指定成员自己的 `kind='must_do'` 记录；无「编辑他人必做项」的合法路径。
- **条目边界**：条目归属该成员的 payload，`id` 仅在该成员列表内唯一；用他人条目 id 提交等同「不存在的 id」→ `400 MUST_DO_ITEM_UNKNOWN`。
- **读边界**：`GET` 返回全员明细（D8），前端只渲染自己那一段。
- **前端边界**：不做本地持久化与离线队列；状态以服务端返回为准；身份来自 `App.jsx` 顶部选择器（1–5）。

## In scope

- 复用 REQ-019 的 `member_preference` 表，新增 `kind = 'must_do'` 的读写；**不新增迁移**。
- `PUT /api/trips/{tripId}/preferences/must-dos`：整表覆盖，服务端签发并保留条目 `id`（D4/D14）。
- `GET /api/trips/{tripId}/preferences/must-dos`：返回全员 `members[].mustDos`。
- 条目校验：`activity` 必填、`location` 与 `time` 至少一项、`time` 严格 `HH:mm`、三字段先裁剪首尾空白（D5/D6/D9）。
- 错误码：`MUST_DO_ACTIVITY_REQUIRED`、`MUST_DO_PLACE_OR_TIME_REQUIRED`、`MUST_DO_TIME_INVALID`、`MUST_DO_ITEM_UNKNOWN`、`MUST_DO_ITEM_DUPLICATE_ID`，并复用 `USER_REQUIRED` / `NOT_A_MEMBER` / `TRIP_NOT_FOUND` / `INVALID_REQUEST`。
- 偏好页的必做项段：列表、添加/编辑内联表单、删除动作、每动作即时保存；loading / empty / saving / 失败四类状态。
- 后端接口测试（含条数、id 稳定、跨成员隔离的写前后断言）+ 前端构建与浏览器观察。

## Out of scope

- 兴趣（US-019，REQ-019）：端点、payload、页面保存按钮均不改。
- 约束与预算两类偏好（US-024 及其后的 `kind`）。
- 「我没有特别偏好」显式态（US-027）与就绪门控（US-026）：必做项保存不改变就绪状态。
- 主线生成与「必做覆盖」校验（US-031/US-037）：本需求只提供数据，不消费。
- 主线确认后锁定偏好：沿用 REQ-019 的 D4 裁定，仅测试上下文，不设锁定分支。
- 条目的排序拖拽、跨成员共享必做项、他人条目的点赞/认领。
- 条目数量上限、长度上限、同名条目的去重：AC 未规定，本轮不实现（记录在 OQ）。
- 真实鉴权：`X-User-Id` 直接信任。
- 新表、新迁移、新组件库、新路由库。

## Constraints

- **技术栈**：Spring Boot 3.5 / Java 21 / `JdbcTemplate`（无 ORM）/ SQLite / Flyway；前端 React + Vite，沿用 hash 路由、`api.js`、`app.css`，不新增依赖。
- **存储**：复用 `member_preference`（`kind='must_do'`，payload `{"items":[...]}`）；`V4` 由 REQ-019 建立，本需求**不新增迁移**；合入顺序硬前置：`V4` 必须在 main。
- **响应风格**：成功裸 DTO，失败 `{"code","message"}`；错误 advice 与 REQ-019 同在 preference 包。
- **身份**：`X-User-Id`（整数），不引入 `X-Member-Id`。
- **固定时间**：`time` 仅 `HH:mm`，日期隐含为该 trip 的行程日期；不做时区换算。
- **页面**：与 US-019 同页 `#/trips/{tripId}/preferences`；兴趣段仍是显式「保存」，必做项段动作即保存（D12）。
- **夹具**：用户与 trip 来自 `acceptance-test-fixtures.md`；US-020 的行为样例由本条目场景表补充，是否回填夹具文件见 OQ-10。
- **文档语言**：本需求 P1 产物用中文，标识符与命令保留原文。

## Affected capabilities

- **修改**已有能力 `preferences`（REQ-019 引入）：新增必做项读写契约，并修订其页面契约（同页新增必做项段、写入时机按段区分）。
- **不改** `trips`（REQ-003）与 `invitations`（REQ-004）的契约；只读复用 `trip_member`、`trip` 与成员判定。
- **不新增**迁移：与 REQ-004 的 `V3`、REQ-019 的 `V4` 均无编号竞争。
