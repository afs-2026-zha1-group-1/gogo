## Intent

补齐分队链的「可编辑 + 可继续」收口：第 2 步不再只是展示生成结果，而是允许任意行程成员就地修正活动名称、地点与三项时长；「下一步」承担保存与时间窗校验两个动作，校验通过后进入只读的队伍路线预览（复用 Screen 11 图），不通过则以弹窗给出可操作的失败原因。确认仍由服务端从草稿复算，编辑值必须先落库，杜绝「下一步通过、确认失败」的口径分裂。

## Actors and boundaries

- 读取：任意行程成员可读 `GET split-draft`（既有 member-only）。
- 写入：`PUT split-draft/routes` **任意行程成员**可调用（BQ-6）；重新生成 `POST routes:generate` 仍仅发起人（US-042 不变）。
- 身份/行程/成员前置：无会话 → `401 MEMBER_REQUIRED`；未知行程 → `404 TRIP_NOT_FOUND`；非成员 → `403 NOT_A_MEMBER`。
- 草稿状态：仅 `active` 可保存与继续；`confirmed` / `cancelled` 只读（保存 → `409 SPLIT_DRAFT_NOT_ACTIVE`）。
- 版本：写操作使用 `draftVersion` 乐观锁，失配 → `409 STALE_DRAFT_VERSION`，不得部分写入。
- 判定边界：时间窗可行性由后端 `ReunionTimingCalculator` 决定；前端只渲染 `feasible` / `overrunMinutes` / `missingInputs`，不自行宣布可行。
- 数据所有权：时长归草稿文档，活动名/地点归 `plan_node`（split-a/split-b）；两者必须在同一事务内更新。
- 不在范围：费用、必做标识、逐节点任务、通知（邮件/推送/队列）。

## In scope

### US-087 — 路线编辑与保存

- 第 2 步 `screen-routes.tsx` / `route-card.tsx`：A/B 路线卡片支持内联编辑
  - 活动名称 `activityName`（必填，trim 后非空）；
  - 地点 `locationName`（可选）；
  - 活动时长 `activityMinutes`、各段路程 `travelLegsMinutes[]`、缓冲 `bufferMinutes`（整数 ≥ 0；路程段数保持不变，只改每段分钟）。
- 新增 `PUT /api/trips/{tripId}/split-draft/routes`：
  - body：`{ draftVersion, routes: [{ groupLabel, activityName, locationName, activityMinutes, travelLegsMinutes[], bufferMinutes }] }`；
  - 恰好两条、`groupLabel` 集合 = `{A, B}` 且与草稿 `groups` 键一致；
  - 单事务更新 `plan_node.title` / `location_name`（split-a/split-b，当前 `planVersion`）与草稿文档 `routes`，`updated_at` 刷新，`draftVersion + 1`；
  - 响应 200：`{data:{draftVersion, routes:[GroupRoute]}, error:null}`（复用 `RouteGenerationResponse` 形状）。
- `GET split-draft` 的 `GroupRoute` **additive** 新增 `locationName`（nullable），旧数据返回 `plan_node.location_name`。
- 前端编辑态：仅草稿 `active` 可编辑；`confirmed`/`cancelled` 只读；无路线对时显示既有空态。
- 权限：任意成员可保存（BQ-6）；生成与重新生成仍仅发起人。
- 错误契约：新增 `INVALID_ROUTE_INPUT`（400，字段级非法值）；复用 `INVALID_ROUTE_PAIR`、`INVALID_GROUP_LABEL`、`SPLIT_DRAFT_INCOMPLETE`（`details.missing = routes.A / routes.B`）、`STALE_DRAFT_VERSION`、`SPLIT_DRAFT_NOT_ACTIVE`。

### US-088 — 下一步校验与队伍路线预览

- 第 2 步底部「下一步」改为复合动作：
  1. 有改动 → 先 `PUT routes` 保存（无改动则跳过保存，不产生版本变更）；
  2. 保存成功后 → `POST routes:check-timing`，快照取当前 B/A 路线与 `windowMinutes`；
  3. `feasible = true` → 进入第 3 步「队伍路线」预览；
  4. `feasible = false` → 停留第 2 步并弹窗（原因来自 `overrunMinutes` / `missingInputs`）；
  5. 保存或校验请求失败 → 页内错误提示，保留输入，不跳转。
- 第 3 步改为 `screen-preview.tsx`（新路由 `/trips/:tripId/split/preview`）：
  - 复用 `TeamRouteGraph` + `buildGraphRows`，展示主线、分头、A/B 分支、会合与暂停段；
  - 标题「队伍路线预览」、副标题「校验通过 · 只读预览」、顶部 A 组 / B 组人数徽标；
  - 只读；底部「前往复核并确认」→ 既有 `/split/confirm`；返回第 2 步；
  - 状态覆盖 loading / error / 无草稿 / 无路线对 / 终态只读。
- 旧 `/trips/:tripId/split/timing` **重定向**到 `/split/preview`（保留旧书签与深链可用；D-1）。
- `screen-confirm.tsx` 的 `backTo` 改为 `/split/preview`；stepbar 仍为 2/3/4。
- 时间窗失败弹窗：新增 shadcn 风格 `components/ui/dialog.tsx`（受控 open、遮罩不可点外关闭）；内容为判定结论、A/B 组各自合计分钟、时间窗分钟、超窗分钟（如有）、缺失输入项（如有）；底部仅「关闭」，不自动跳转，关闭后焦点回列表。
- 校验接口与判定逻辑不新增（复用既有 `routes:check-timing` 与 `ReunionTimingCalculator`）。

## Constraints

- 技术栈不变：Spring Boot + JdbcTemplate + SQLite + Flyway；React + Vite + TS + shadcn/ui；**零迁移、零新依赖**（地点复用既有 `plan_node.location_name`）。
- 保存原子性：`plan_node` 两行更新 + 草稿文档 `routes`/`updated_at` + 版本 CAS 在同一事务；任一步失败整体回滚。
- 版本语义：保存成功后 `draftVersion + 1`；`boundaries`/`generate`/`assignment` 的既有版本语义不变；`confirm`/`cancel` 不变。
- 判定归后端：前端不得根据本地分钟数宣布可行；弹窗数值来自 `check-timing` 响应。
- `check-timing` 契约不扩展（仍为只读快照，200 + `feasible`）。
- 展示规则：`locationName` 为空或等于 `activityName` 时不重复渲染地点行。
- 路由与返回：不使用 `navigate(-1)`；返回目标显式携带 trip 上下文（US-082）。
- 430px shell 内不横向滚动；编辑控件不遮挡卡片标题与状态标签。
- 确认与取消的只读终态不被编辑能力放宽。
