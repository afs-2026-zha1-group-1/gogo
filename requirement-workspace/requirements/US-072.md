## Intent

在行程详情页为所有已登录成员增加一条显眼的"查看主线方案"导航入口，使成员在分队前能方便地查看行程安排。入口本身不引入新逻辑，仅路由跳转到已有的 MainPlan 页面。

## Actors and boundaries

- 入口对所有行程成员可见（不区分组织者/普通成员）——因为主线方案是全员可读的共享资源。
- 权限和登录拦截由 App.tsx 的 route-level auth guard（`status !== 'signedIn'` → LoginPage）和后端 API 的 session 鉴权处理，本故事不新增任何鉴权。
- 页面跳转使用 hash 路由 `#/trips/{tripId}/main-plan`，由现有 `parseRoute` 匹配并渲染 `<MainPlan>` 组件。
- 返回路径：MainPlan appbar 右侧 info 图标按钮（`href="#/trips/${tripId}"`）已存在，满足 AC4；左侧箭头和浏览器返回也自然可用。

## In scope

- TripDetails.tsx 中 `InvitationPanel` 组件之后、"分队规划" section 之前，新增一个 section：
  - `sec-title` 标题 "主线方案"（带 sparkle/info 图标）
  - `card pad` 容器内一个 `<a className="btn btn-primary" href="#/trips/{tripId}/main-plan">` 入口链接，文案"查看主线方案"
- 该入口对所有 trip 成员可见（与 trip 是否已有方案、是否已确认无关——进入后由 MainPlan 页面自行处理 empty/ready 状态）。

## Out of scope

- MainPlan.tsx / MainPlanInputs.tsx 的任何逻辑或 UI 变更。
- 后端 API、路由、鉴权、数据模型。
- 邀请（InvitationPanel）和分队规划 section 的行为、样式或位置。
- App.tsx 的 parseRoute 或 TabBar 改动（路由已存在）。
- 修改 MainPlan 左侧返回箭头目的地（当前到 `#/`；这是 UX 微调，属后续独立改进）。
- 新增"方案未确认时禁止分队"等跨功能门控——分队规划 section 已有 `mainPlanConfirmed` 逻辑，不改变。

## Scenarios and AC hints

| id | Scenario | Observable outcome |
|---|---|---|
| AC1 | 成员 Ben 打开行程 "Singapore Friends Day" 详情 | 页面中"邀请朋友"section 下方、"分队规划"section 上方可见标题为"主线方案"的卡片，内含"查看主线方案"链接 |
| AC2 | Ben 点击"查看主线方案" | 页面跳转到 `#/trips/1/main-plan`，显示主线方案时间线和状态（草稿/已确认） |
| AC3 | 组织者 Alice 打开一个尚未生成方案的行程详情并点击入口 | 进入 MainPlan 页面，显示"还没有主线方案"空状态，组织者可见"去生成主线方案"按钮 |
| AC4 | Ben 从入口进入 MainPlan 后点击 appbar 右侧 info 按钮 | 返回 `#/trips/1`（行程详情页），内容未变化；未触发任何 POST 请求 |
| AC5-N | 未登录用户直接访问 `#/trips/1/main-plan` | 显示登录页面（现有 route guard），不展示方案数据 |
| AC5b-N | 已登录的非成员 Eve 直接访问 `#/trips/1/main-plan` | MainPlan 页面显示"没有访问权限"（现有 denied 状态），不展示方案数据 |
| AC6 | 网络异常或后端返回错误时 Ben 点击入口 | MainPlan 页面显示"无法加载主线方案"+ 重试按钮（现有 failed 状态） |

## Constraints

- 仅修改 `frontend/src/pages/TripDetails.tsx`，无新文件。
- 沿用既有 CSS 类名（`sec-title`、`card pad`、`btn btn-primary`），不引入新样式或依赖。
- 链接使用 `href` 而非 `onClick` + `window.location`，保持与"设置我的兴趣"入口一致的 SPA 锚点风格。
- TypeScript 类型不变（无新增类型/接口）。
