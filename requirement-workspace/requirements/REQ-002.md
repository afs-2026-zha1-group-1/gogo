## Intent

Apply three named IO rulings to the shipped REQ-001 slice without changing what
the visitor sees: keep Flyway, switch the response body to JSON, switch the
embedded engine from H2 to SQLite.

## Actors and boundaries

Unchanged from REQ-001. Visitor reads the home page; backend owns the `greeting`
table and the read endpoint; frontend owns rendering and must not contain the
literal greeting.

## In scope

- `GET /api/greeting` returning `application/json` with body
  `{"message":"<stored message>"}`.
- Frontend reads the JSON `message` field instead of the raw response text.
- Embedded **SQLite** file database at `backend/data/gogo.db`, created and seeded
  by Flyway on first start.
- Backend acceptance tests run against SQLite, not H2.
- Verification commands, verification matrix and `README.md` updated for the new
  engine and media type.

## Out of scope

All REQ-001 non-goals stand: no ORM, no user accounts or permissions, no greeting
management UI or write API, no i18n, no production deployment or CD trigger.
Additionally out of scope here: migrating existing H2 rows (the local `data/`
directory is gitignored dev state and the seed is a constant), changing the CI
job structure, and adding fields to the JSON envelope.

## Scenarios and AC hints

| id | Scenario | Observable outcome |
|---|---|---|
| AC1 | `GET /api/greeting` with the seeded row present | HTTP 200, `Content-Type: application/json`, body `{"message":"Hello World"}` |
| AC2 | Stored message changed to another value | The JSON `message` field carries the new value |
| AC3 | Open the home page with the backend running | The heading shows `Hello World`, obtained by parsing the endpoint JSON |
| AC3-N | Open the home page with the backend stopped | A load-failure message, no greeting heading |
| AC4 | Start the backend with no database file present | `backend/data/gogo.db` appears and holds exactly one `greeting` row with message `Hello World` |
| AC5 | Restart against the existing file | The row is still `Hello World` and the row count is still 1 |
| AC6-N | `POST` / `PUT` / `DELETE` to `/api/greeting` | 405, stored row unchanged |

AC1 supersedes REQ-001 AC2. AC4/AC5 restate REQ-001 AC1 against the new engine.
AC3/AC3-N/AC6-N are unchanged in observable terms and are re-verified because the
transport and the storage engine both changed.

transport-agnostic and are re-verified, not rewritten.
